# 老王篮球高光剪辑 · Basketball Highlights YOLO

固定机位（三脚架 · 半场单篮筐）的篮球视频 → 自动找出进球 → 合成集锦 + 竖版短视频。

自训 YOLOv8n 只检**篮筐 ROI 内的球**，靠「穿筐几何 + 篮网运动证据」判进球，再按三档置信度交给人裁决。
定位是**高召回候选 + 人工勾选兜底**，不是全自动——不勾选直接发片会带假进球。

> 环境要求、安装、上手步骤都在下面；**开发过程与工程细节记录**在文末，使用本项目不需要读。

## 一、你需要准备什么

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10 / 11 | 脚本是 `.bat` / `.ps1`。mac / Linux 能跑，但要手敲命令 |
| Python | **3.12** | `torch 2.5.1` 最高支持到 3.12，3.13 装不上 |
| 显卡 | NVIDIA 独显（8G 显存够用），**推荐** | 纯 CPU 能跑，但一小时的片子要等很久 |
| 磁盘 | 约 6GB | 依赖约 2.5GB + 权重 + 中间产物 |
| 视频素材 | **固定机位 · 三脚架 · 半场单篮筐** | 这条是硬前提，手持运镜效果会很差 |

以下都不用你另外装：ffmpeg（随 `imageio-ffmpeg` 打包）、Node.js（前端产物已在 `bbh/static/`）、模型权重（在 `bbh/weights/`）。

## 二、安装（Windows，约 15 分钟）

在 PowerShell 里执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

它会建 `.venv`（用 `py -3.12`）、装依赖（PyPI + PyTorch CUDA 12.1 源），最后打印 `torch 版本` 和 `cuda True/False`。
看到 `cuda True` 就说明显卡路径通了。

**纯 CPU 用户（没有 NVIDIA 显卡）**要多改三处：

1. `requirements.txt` 里 `torch==2.5.1+cu121`、`torchvision==0.20.1+cu121` 的 `+cu121` 改成 `+cpu`
2. `scripts\install.ps1` 里的 `--extra-index-url https://download.pytorch.org/whl/cu121` 换成 `.../whl/cpu`
3. `run_app.bat` 里加一行 `set BBH_YOLO_DEVICE=-1`

装完体积会小很多（约 300MB 而不是 2.5GB），代价是慢。

## 三、跑起来

```bat
run_app.bat
```

会自动打开浏览器（`http://127.0.0.1:7860/edit.html`，端口被占就自动往后顺延，控制台会打印实际地址）。

## 四、用起来（6 步）

1. **⚙ 标定**：传一段该机位的短视频 → 抽帧 → 点**筐口左端、右端、球** → 生成标定
   （**每个视频都要标一次**，这是硬要求，不是可选项）
2. **上传视频** → 开始检测，等它跑完（一小时片子大约十几分钟，看显卡）
3. **三档裁决**
   - **高置信**：默认勾选，通常直接可用
   - **待确认**：**重点看这一档**，用预览逐条裁决，这一步决定了最终质量
   - **低置信**：查漏用，一般不用管
4. **生成集锦**：选保留的片段 → 出片
5. 需要发短视频就**导出竖版**（纯黑留白，画面高度用 `content_scale` 调）
6. 出手人会自动溯源到人（HSV 球色 + person 框裁缩略图），不用手动标球员

## 五、效果到什么程度（实话）

| 指标 | 实测 | 说明 |
|---|---|---|
| 真球被自动判定出的比例 | 约 **84%** | 剩下约 16% 落在「待确认」，需要你手动勾 |
| 机器报出的进球里，真正是进球的比例 | 约 **79%** | 随场地在 **63%~92%** 之间波动，差别很大 |
| 完整人工勾选之后 | **≈99%** | 这才是设计目标 |

数字来自 18 场自有录像、5 套固定评测口径（判定逻辑 v24），可复算但**不可跨场地外推**。
换句话说：**它的价值是替你把一小时片子筛成几十条候选，不是替你判断对错。**

## 六、关于模型（务必读）

- `bbh/weights/best.pt` 是**自训权重**，训练数据只有我们自己的场地和球（球 / 筐两类）。
  换球场、换球色、换光照，检出率大概率下降——**这是本项目最大的隐性门槛**，不是免责套话。
- 兜底方案，按代价从小到大：
  1. **重新标定**（很多时候问题出在标定，不在模型）
  2. 用自己的数据补训（见 `docs/` 里的方案文档）
  3. 设 `BBH_DETECTOR=hsv` 退回 HSV 颜色检球（不依赖模型，但对球色和光照敏感）
- 检测器可随时切换：`BBH_DETECTOR=yolo`（默认）/ `hsv`（对照），启动脚本 `run_app_hsv.bat` 就是 HSV 版。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `pip install` 卡在 torch | 在下载约 2.5GB 的 CUDA 轮子，等着就行；或改走 CPU 版 |
| 装完 `cuda False` | 显卡驱动太旧，更新 NVIDIA 驱动；或本来就是纯 CPU 机器 |
| 检测很慢 | 设 `BBH_YOLO_STEP=2` 隔帧取（省一半时间，召回略降）；确认 `BBH_YOLO_DEVICE=0` |
| 球检不到 | 先重标定；再试 `BBH_YOLO_CONF=0.01`；仍不行就换 `BBH_DETECTOR=hsv` |
| 端口被占 | 不用管，端口会自动顺延，看控制台打印的地址 |
| 想回归测试自己的改动 | `.venv\Scripts\python scripts\run_tests.py` |

# YOLO 篮球进球自动集锦工具（自训 YOLO 检球版）

固定机位（三脚架、半场单篮筐）篮球视频自动检测进球并合成集锦。
**本项目把「检测球」这一步换成了自训 YOLO 模型**（原项目用 HSV 颜色检球）。

## 与本仓库的关系（独立工程，零耦合）

- 本仓库**独立 fork** 自「视频剪辑」项目（`bbh/` 判定/渲染/前端全套照搬，
  冻结在其 v18 提交 `3b11861`），此后独立演进、按需手动同步上游增量
  （如 `8e9839b`）；**v19 起重大判定变更两仓协同改**（上游 `1fde879` /
  本仓 `ac43dea`，常量与验收口径保持一致）。
- 代码**不依赖、不引用**原项目任何一行：`bbh/` 内无绝对路径、无跨仓库 import。
- 两仓的结构性差异集中在检出层与标定页：
  1. **主检测**换成 YOLO（`bbh/detector_yolo.py` + 随包权重 `bbh/weights/best.pt`）；
  2. **静止链过滤**默认改成 `b1m`（`bbh/static_filter.py`，补齐被误删的悬停真球）；
  3. 标定预览按检测器分流（YOLO 模式画真检测器球框，R-013）。

### 检球器开关

| 环境变量 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `BBH_DETECTOR` | `yolo` / `hsv` | **`yolo`** | 主检测用哪个实现（`bbh/detector_switch.py`） |
| `BBH_STATIC_FILTER` | `orig` / `b1` / `b1m` | **`b1m`** | 静止链过滤策略（`bbh/static_filter.py`） |
| `BBH_YOLO_WEIGHTS` | 路径 | 包内 `best.pt` | YOLO 权重 |
| `BBH_YOLO_CONF` | 浮点 | `0.03` | YOLO 置信度阈值（低阈值=召回优先） |
| `BBH_YOLO_STEP` | 整数 | `1` | 采样步长（1=每帧都看） |
| `BBH_YOLO_IMGSZ` | 整数 | `1024` | 推理分辨率（整帧构图） |
| `BBH_YOLO_CROP` | `full` / `roi` | **`full`** | 推理构图：`roi`=筐周 ROI 裁剪。**遗留**：标定预览（R-013）仅与 `full` 同参，`roi` 模式预览未对齐（该开关现无使用方） |
| `BBH_YOLO_QUANTIZE` | `16`/`8`/`None` | `16` | 精度（16=FP16，None=FP32，8=INT8） |
| `BBH_YOLO_DEVICE` | 整数 | `0` | GPU 序号（`-1`=CPU） |
| `BBH_PERSON` | `on` / `off` | **`on`** | 出手人缩略图 person 框裁剪（`bbh/person.py`） |

`run_app.bat` 已把 `BBH_DETECTOR=yolo` 显式设好；`run_app_hsv.bat` 一键切回
HSV 版本做对照。检出器名并入了检出流缓存指纹（`DETECT_VERSION`），**切开关
会自动作废旧缓存、不会误吃**。

> 说明：本次只换**主检测（A1）**。出手人识别里的「出手回扫」与竖屏运镜里的
> 「跟球链」仍走 HSV（下文「出手人识别」节原样有效）——那两处属于后续可替换项。

### 出手人缩略图 person 框（`BBH_PERSON`）

射手缩略图原来按出手点定宽居中裁剪，远景下常拍不到完整的人。2026-10-15
spike（36 球两场实录，0 认错）后收编：COCO 预训 `yolov8n` 检人（权重随包
`bbh/weights/yolov8n.pt`），归属用**球锚**——出手时刻球在谁手上谁就是出手人
（HSV 球块落谁的框就归谁，出手点只做兜底锚点），裁剪换成 person 框 + 45%
边距。归属档记录在 `shooters.json` 每球的 `person` 字段（`ball`/`in`/
`expand`/`near`/`none`，前端暂不显示）。参数版本 `person_ver` 过期只重裁
缩略图、不作废溯源缓存；`off` / 权重缺失 / 推理异常自动退回出手点定宽裁剪。

## 能力边界

八场标准测试集（v12 四场 + 2026-09-13/09-23 两轮扩场，现行判定 v24）。
自动判定查准率 65%~92%（按机位/场地差异大），查全率 74%~95%——设计定位
是**高召回 + 人工勾选兜底**：三档置信列表帮你把数百条候选缩到百余条真进球，
人工勾选后集锦准确率 99%+。不要指望全自动零复核。

**v19 官方口径六场（2026-10-18 上线，R-020 判定层 hard-case 调优）**：主臂
（YOLO）查准 60.80%→**66.18%**（+5.38pct）、查全 82.88%→82.23%、假绿
412→324、自动档 1051→958；副臂（HSV 对照）查准 72.96%→76.77%。进度与
数字的唯一台账 = `docs/需求池.md` R-020，详报在 YOLO 训练仓
`yolo/reports/KPI_官方口径_v19.md`（不随本仓分发）。

> ⚠️ 上面这段是 **v19（2026-10-18）上线当时的官方口径记录**，属历史快照。当前生产
> 判定已到 **v24**（2026-11-14，穿筐物面积硬门），v20~v24 的变更与各版数字见下文
> 「判定逻辑版本史」。**不同版本的数字不可混用**——换版只重判不重扫，旧版 events
> 跑出来的数字不代表当前代码。

**YOLO 检出（7 场 890 球，对称口径）**：与 HSV 基准相比——判定/覆盖基本持平
（等价容差下全 7 场查全差 1.5pt），剔除单场异常后反超；余下短板是「远端高分
噪声略多」。完整对比见专项报告（不随本仓库分发）。

## 使用

1. 双击 `run_app.bat`（首次先完成下方「安装」）
2. **⚙ 标定设置**（每个视频各一次）：上传一段日常短视频或填本机路径 → 抽帧 →
   在帧上依次点击筐口左端、右端、球（1-3 次；球需在黄框内——黄框=检测
   区域，覆盖篮下禁区，球大致在篮下就行）→ 生成标定；必要时微调 HSV。
   （**YOLO 模式下**：标定仍必做——筐口几何是判定器的输入；预览叠加画
   **真检测器**的球框——R-013 起标定预览按检测器分流，YOLO 模式走
   `calibration.yolo_overlay`，预览所见即检测所查。点选球色与「微调 HSV」
   仍要认真做——它们是 HSV 对照路径与**出手人溯源**回扫的种子色域
   （退役路线已被 R-016/R-017 数据否决），只是不再影响 YOLO 主检测。）
   点筐的那帧会存档为参考帧（`calibration_ref.png`，与标定文件同目录）——
   检测期间拿它做镜头位移校正（见「工作原理」）；**请在画面稳定后抽帧
   标定**，不要用还在调试准备阶段的首帧。
   **标定随视频走**（2026-09-13 起）：标定存进 `work/<视频名>/` 各存各的，
   换视频不再沿用上一个视频的标定——新视频没标定会明确提示，切回旧
   视频自动恢复它的标定；检测/出手人等全部只认本视频目录里的标定。
   旧版存在仓库根的全局标定，程序启动时按 `events.json` 指纹自动认领
   搬进对应视频目录（无人认领的原地不动，交自己归置）。
   **中途挪过镜头的视频用多段标定**：主标定照常标片头机位，检测完成后
   若结果带「镜头大幅移动」警告，回本页跳到新机位时间点抽帧补标一段——
   各段只信自己的几何，旧段的检出缓存原样吃回，只有新标的那段重新扫
3. **剪辑台**（每周主力页）：填视频完整路径 → 已有结果自动载入，否则点
   「▶ 开始检测」（后台续跑，完成后自动载入进球列表；没标定会先提示去
   「⚙ 标定设置」；**检测中刷新/关闭页面 = 取消检测**，进度存检查点，
   重新点开始从断点续跑不白跑）
4. 复核打标：列表三档色点——🟢 高置信 / 🟡 待确认 / ⚪ 低置信（否决门槛
   拦下但保留的投篮候选，仅供人工查漏；判定依据里写明降级原因）。
   **默认全部不勾选**（包括高置信）——你勾哪些就出哪些；勾选每次改动
   即时存档（`work/<视频名>/selection.json`），重开页面/重启程序不丢，
   重跑检测后对不上的旧勾选自动作废。点列表任意行 → 右侧立即预览
   （分色进度条：蓝=进球前 / 红线=进球时刻 / 绿=进球后）；视频下方一行
   复核工具：点行后「✅ 是进球 / ❌ 未进球」裁决该行（同一按钮再点一次 =
   取消；⚪ 低置信但实际进了的，点「✅ 是进球」翻案），「漏检时刻」框记录
   列表里完全没有的进球（mm:ss 或秒数，大致即可）；统一调整切片长度=
   点底部「⏱ 时长」按钮弹窗里改「全局 前/后(秒)」→「应用到全部」（低频
   操作收进弹窗，平时不占列表空间）；打标签=先点行选中，再在「标签」
   下拉里选（清空=去掉标签），新人名点「➕ 新增」入库；**选了标签的行
   自动勾选**——打标即认定进球，省一次点击（清空标签不会取消勾选）。
   「🗑 删除此球 / 🗑 批量删除」=把比赛间隙的随意投篮整行移出（可恢复，
   级联清归人/勾选，键=原始检测时刻）；「⚠ 缩略图有误 / ✚ 十字有误」=
   给出手人图的问题打标（独立存档，供缺陷归因分析，不影响判定）
   - **识别出手人**：复核前点左栏「🧍 识别出手人」——每球自动回扫进球前
     几秒找出手点、生成射手动图（约每球 3 秒，跑一次进缓存，重开页面
     不重跑；已识别的球自动跳过）。点列表任意行 → 右侧面板显示射手动图
     （出手前 0.7s + 后 0.4s；红十字=估计出手点，逐帧十字跟随球移动；
     定位失效的球——出手点在筐平面以上或贴画面边——自动退全场图+⚠ 角标。
     🟢 轨迹完整 / 🟡 轨迹存疑 / ⚪ 未溯源——🟡 的出手点位置可能偏、
     ⚪ 没追到，这两种回看视频打标），**看图打标签**，
     不用逐条回看视频找出手人

   → 🎬 生成集锦 MP4 弹窗勾选要出的视频：**视频合集**（全部勾选的进球，
   `highlight.mp4`）默认勾选，可加勾任意标签——每个勾选的标签各出一部
   「勾选且带该标签」的集锦（`highlight-<标签>.mp4`），某标签没有勾选进球
   则跳过并汇报，并附按人统计的进球数（未标注归「其他」）。生成中左栏
   结果区逐项显示 `⏳ 正在生成（k/N）` 进度，完成后出 `✅` 报告。
   片段不合并——每个进球独立成段
   - 产物在 `work/<视频名>/highlight.mp4`，单片段在 `work/<视频名>/clips/`
   - **判定依据怎么读**：右侧面板随行显示判定依据（下穿点在筐口的位置、
     上/下方证据点数与时间跨度、**下方证据的下落步长**、**穿筐后的球体
     点数**、疑似弹出提示）与置信度算式——高置信直接过，待确认的看预览
     人工裁决。下落步长与球体点是关键：真球穿筐后快速下坠（步长大）且
     会以球体量级再次被检出（球体点 ≥1）；原地不动的"下方点"是筐下
     固定物或被抱住的球，"穿过即消失"的大块是弹飞的球或人肤横穿——
     前者不成进球，后者保留为待复核
   - **时刻校准怎么用**：检测时刻整体偏早（进球标早了）填**正数**整体后移、
     偏晚填负数；控件在左栏**「更多调整」折叠区**里，改完点「重新载入」

## 工作原理

### 检测判据链（YOLO 检出 → 静态滤除 → 穿筐几何）

**检出层（本项目改动处）**：YOLO（`bbh/detector_yolo.py`）在整帧上推理，每帧取
**置信度最高**的一个球框，输出位置序列（`BallPos`，面积=等面积圆估算 `π/4·bw·bh`）。
默认低阈值 `conf=0.03`、每帧都看（`step=1`）——召回优先，把判定器需要的
「同侧 ≥2 点且跨度 ≥0.2s」证据给足。原 HSV 路径（颜色→面积→形状）仍保留在
`bbh/detector.py`，用 `BBH_DETECTOR=hsv` 切回。

**判定层（与原项目逐字相同）**：检出流 → 筐口平面 ±1/4 筐高条带忽略 → **时间维度静态滤除**
（同格内 ≥3 个检出连成"静止链"（逐点步距 ≤3px）→ 篮网结点、筐下固定橙物等，
整链剔除；间歇出现的小段也删，真球步距大只会断链）→ **下落校验**（下方证据
原地不动/上弹 → 不构成进球）→ **下落实体校验**（穿越筐口后须再检出球体量级
大块（≥0.1×筐矩形面积——真球与固定物/皮肤碎片面积差一个量级））。

被否决门槛（几何拦截/无下落/无球体/证据不足）拦下的候选**不再删除**——
降为 ⚪ 低置信档进列表供人工查漏，默认不勾选、不进集锦。单帧预览看不出
这几层。预览与检测同一套过滤（YOLO 模式下预览同样走模型），预览里被染绿的
才会被检测当成球。

### 镜头位移校正

固定机位中途被碰/缓慢漂移时：检测期间每 5s 拿当前帧与**标定参考帧**做
ORB 特征匹配，测出镜头位移后把检测 ROI 和检出坐标都折回标定坐标系——
被碰后（实测本机样本右跳 +32px）筐口矩形依然全程有效，真进球不会被
"球心出筐口两端"几何门槛误杀。旧标定（没存参考帧）检测时会有
「位移校正未启用」提示，重新生成一次标定即可启用。

已知残留与边界：①碰镜瞬间后的短暂"配准空窗"（碰镜造成 y 向视差大，
采样被连续拒绝）会让空窗内事件的穿越点坐标有偏差——修复方案（y 轴
MAD 放宽+重试）已验证待实施；②**手持拿起挪动放下（物理平移）视差会
打死单参考帧假设**——远近物体位移不同，旧标定原理上映不过去（实测
墙面 vs 筐位移差 3 倍+）。此时检测结果的警告栏会提示「镜头大幅移动，
建议分段标定」；到「⚙ 标定设置」跳到新机位时间点补标一段即可——
多段标定下各段只信自己的几何与参考帧，跨段事件照常冷却合并，旧段
缓存零重算。

### 篮网运动证据（v12 起，v18 进置信度，v19 加重）

球穿网必撑开网并持续摆动 ~1s；从筐前/筐后净空飞过或未触网则网保持静止。
对**每个事件行**测「事后窗网区帧差」——球过筐后 0.45/0.70/0.95s 三窗各取
5 帧差分取最大（网区随镜头位移逐帧平移、帧间相位相关对齐后差分，同画面
对照区同步测作噪声底）。

**规则是单向证据**：网静止 ⇒ 大概率没进；网动**不**升级——打铁蹭网/
砸筐传振同样让网强烈摆动，真进的"纵向撑开"与擦网的"侧向甩摆"在帧差
能量上不可分（truth 三场 5 例边界目检定性）。测量失败（视频打不开/
seek 出界）fail-open 不扣分——证据缺失不能当否证。信号存
`net_signals.json` sidecar（身份=视频+筐标定+参数版本），重放判定
命中缓存零视频 IO。

**落地机制（v18 起，取代 v12/v14 的一票降档）**：网信号是置信度的
**加减分项**——网静止 −0.30、网亮但非局部 −0.26、网动/未测 0（v19
加重；v18 定稿时为 −0.20/−0.10）。非硬门行按含网分的 conf 对
`HIGH_CONF`（0.60）/`MIN_CONF`（0.50）重分箱；硬门行（low_reason /
review_reason / pop_back）测网只记录、档位不动。

**局部性门（v14 起）**：网区帧差会被**画面级**抖动/编码噪声抬亮（取证：
假绿差分热力图整框无结构椒盐、肉眼网完全静止、对照区等亮）——
"网动了"必须是**那一对帧里网区比对照区亮得多**。规则：post≥5 且
存在一对 n ≥ 3×c（同一对帧上比；两头等亮=全局抖动/编码噪声伪装）。
五场真值分布验证（post≥5 行，FP=160/TP=583）：k=3 拦假绿 64（40%）、
真绿误杀 17（3%，进球恰逢镜头大幅移动，物理不可分，人工勾回）。

### 出手人识别（Phase 1）

进球判定只看筐口周边；出手点在三分线，检出流从不覆盖。识别出手人时
对每个进球**按需回扫**进球前 6 秒的全帧画面（复用同一套 HSV/形状/筐带
判据，隔 2 帧采样 ≈15fps，每球约 3 秒），从进球穿越点倒序回追球的轨迹
（0.5s 缺口桥接；每帧多块候选 + 筐口闪斑/静点剔除 + 方向门控防串到
传球或场下球），找到"持球慢移→离手加速"的速度跃变点 = 出手点
（跃变须在筐平面高度以上，防飞行段误停），在其下方按筐宽标尺
（筐直径 45cm；出手点深于筐平面越远、裁框越大）裁出射手全身
动图（出手前 0.7s + 后 0.4s、9 帧，十字逐帧跟随球——被手遮挡的帧
十字诚实消失而非跳到别人身上；出手瞬间/前 0.3s 两帧 jpg 同步存档）。
出手点物理校验（筐平面以上=链追到窗口边界球还在飞、或贴画面边=窗口
截断估计）不通过 → 不裁框不画十字，改存全场下采样图 + ⚠ 角标
（定位失效兜底）。三档置信：🟢 轨迹完整且找到
跃变 / 🟡 轨迹短或追到窗口边界（出手点可能偏）/ ⚪ 未溯源。

回扫与 GIF 跟球的 S 下限不低于 88（**扫描饱和度地板**，SHOOTER_VERSION
v4）：远景机位球只有几像素，标定易点到运动模糊的低饱球像素把色域撑宽
（09-04_1 段 1 实测 S=37——顶棚暖反光 S 37~80 全过颜色范围，全帧回扫
67~81% 检出是顶棚静块、链被劫持，89/119 球定位失效）；真球高饱和不受
影响（该段 119 球全量重放：定位失效 74.8%→5.0%，🟢 完整轨迹 8→85），
对 S 下限 ≥88 的标定是 no-op（四场已验收场 88/90/90/140）。地板只作用
扫描口径——标定数据不动：主检测用收紧 HSV 全片对照实测会丢 2 个 high
真进球（穿越帧模糊球像素饱和度不足）。标定保存时 S 下限 <60 也会给
知情提示（远景小球常见坑，提示不阻断）。

链首在飞的抛物线回推（SHOOTER_VERSION v5）：远景机位深位出手时上升段
球太小+运动模糊，HSV 逐帧放宽实测 0 检出，链只含下降段 → 链首=弧顶
被当估计点，而「出手点高于筐平面=不可能」的老 A 类校验前提是看台
俯视几何——远景透视下深位出手人合法高于筐平面（09-04_1 段 4 实测
46/219 定位失效主因）。v5 对下降段拟合抛物线（护栏：点数≥5、时长
≥0.25s、y 残差 RMS≤0.5 筐、拟合出上开口），从拟合弧顶回推 0.40s
（投篮上升时长物理典型，尺度无关）当出手估计，状态保持 🟡 review
不升 🟢；外推点的筐上容差放宽到 5.5 筐（段 4 实测深位出手点高出
筐平面 0.3~5.0 筐宽），回推出顶棚区（画面顶部 15%）或贴边出框一律
拒绝、诚实保持链首估计判 bad。55 个 spot=bad 全量重放（用
events.json 精确事件时刻——key 反推差 10ms 就会翻转隔帧采样相位、
采到完全不同的帧序列）：33 翻 ok（60%）、22 诚实保持 bad（画面顶部
类 12=链短或回推过冲、贴边 6、中段链短 4）；非外推路径字节级不变
（未外推球估计点 old=new 逐球一致）。

时刻回推+局部复扫（SHOOTER_VERSION v6）：v5 上线后实测 33 个外推球
31 个外推点落在筐平面以上顶棚区——图像空间抛物线外推结构性不可靠
（透视表观曲率同一场 5 倍差，近大远小让二次系数失真），GIF 裁剪框
锚外推点就是拍灯（用户报告 105:43.6 等）；但**时间**估计可靠（上升
0.40s 物理典型、尺度无关）。v6 拆开用：抛物线只出出手时刻 t_rel +
x 一次拟合 vx（真实飞行 vx 恒定，v5 的 x 二次项是噪声），IO 层
`_rescan_release` 在 t_rel 后 5 帧（0.05s 步）逐帧宽松 HSV 复扫找球
（质心过滤：x 在链尾 vx 线性回推 ±2.5 筐带内、y 不高于筐上 3 筐——
段 4 实证 173 个正常球出手点最低≈筐平面），**三连链硬门**：连续 3 帧
两段速度都贴 vx±250px/s 且 y 单调上升 ≥8px——首版两帧拼对被地板
标线/顶棚桁架的等距排列骗出假速度对，三连+y 单调骗不过。命中 →
出手点=复扫实测球块位置（GIF 锚真人）；找不到 → 诚实退 bad（全场图
兜底，不生成动图）。09-04_1 33 个 v5 外推球全量重放（events.json
精确时刻）：30 复扫命中 spot ok、3 诚实 bad；105:43.6 精确命中
(1584,412)；3 球视觉抽验裁剪框内全是出手人+球场（v5 同批是纯顶棚
灯）。已知残缺：红十字偏低属既有 B 类「十字低」——t_rel 抓到的是球
发力期可见的低点位（非举手指尖），抽验两例红十字贴地，但 732px 宽
裁剪框仍完整罩住出手人、GIF 逐帧十字自己跟球走。

动图放大（GIF v2，2026-09-13）：渲染高 240→480（远景接近源框 1:1
真增清晰度，代价 ~1MB/球）；GIF 专用裁剪框在静态 jpg 标尺框基础上
宽 ×1.4、高 ×1.5、出手点竖直位置 0.5→0.6 上偏——框放大吸收复扫
出手点偏低位的偏差，减少「框里没出现出手人」（09-04_1 抽验两例
全身入镜，v6 复扫深位球 65:29.7 头到脚完整）。动图渲染参数带独立
`GIF_VERSION`（ shooters.json 的 gif_ver 字段）：与 SHOOTER_VERSION
不同，过期不作废溯源——只自动清除旧图按新参重生成（🗑 提示）。

跟球双门+钉红调色板（GIF v3，2026-09-13）：旧跟球沿用扫描口径
（S≥88、面积 ≥9px），「离上一帧最近」天然偏向慢速人体——皮肤/头/
手的中饱和块全进候选，球一离手与身体轨迹分叉必输给腿（用户报告
大量十字落在人头人手）。取证双维分离：皮肤/头/手块中位 S 96~136
但成细条 ≤0.035 筐宽²，飞行球 S p5=143、面积 0.12~0.26 筐宽²——
v3 只动 GIF 跟球候选门（扫描/判定/定位口径不动，四场 truth 零
重放）：blob 中位 S≥140（标定 S_hi 更低时自守 S_hi−25）+ 面积
≥0.10 筐宽²，无合格块=十字诚实消失。真代码四球回放：两问题球
从 18 帧全错锁（头/小腿）压到 11 个十字 9 个在球，残留 1 帧
膝盖 1 帧地板（再收紧会吃掉实测下界真球，留给人工兜底）。配套
修 PIL 调色板吞红坑：真场景渐变会吃满自适应 256 色板，~50px 纯
红十字被量化吞掉（编码后红像素=0；480 GIF 此前从未真正生成过，
旧测试没暴露）——首帧定共享 255 色板、纯红钉第 256 槽按索引写
十字（`optimize=True` 按首帧用色裁板会裁掉红槽，必须去掉）。已知
外观限制：红色球衣 RGB≈(253,84,64) 与纯红十字对比度极低，十字
落在红衣上几乎不可见（取证实测；按「十字消失」语义人工核对）。

墙放大+动图再放大（GIF v4，2026-09-13）：用户报「GIF 看不太清」——
主因在显示侧：归人两面墙 Gallery 一行挤 10 格（每格 ~130px 宽），
列数 10→6 格子翻大；渲染高 480→640 跟上像素密度防糊（gif_ver 升 4
自动重生成，423 球 ≈ 7 分钟全自动）。一屏少看几个球多滚动，认人
清楚优先。

缓存 `shooters.json` 身份键 = 视频 + 标定指纹 + `SHOOTER_VERSION`
（独立版本号，与 `DETECT_VERSION`/`LOGIC_VERSION` 无关）——溯源调参
不触发全片重检；逐球写盘，中断重跑只补缺。射手动图 `{key}.gif`
不进身份校验——文件存在性即状态；两类自动清除：身份失效全量重扫
（v6 教训：锚旧出手点的拍灯图会残留冒充新图）、动图渲染参数版本
gif_ver 过期（只清旧图重生成，溯源 traces 不作废）。单独重生成某张
仍须手动删文件。

| 判定结果 | `work/<视频>/events.json` | 视频 + 标定指纹 + `LOGIC_VERSION` | 调判定逻辑 |

自动失效。**核心收益**：调判定参数只 `LOGIC_VERSION+1`，从 positions.json
秒级重放判定器，跳过全片检测（110min 视频 → 秒级）。

### 一键评测（三口径报告）：`scripts/eval_report.py`

八个 `tools/evaluate.py` 是**逐场**看数；要**汇总 + 分口径**看整体，用评测套件
（`tools/eval_lib.py` + `scripts/eval_report.py` / `scripts/run_eval.py`）。它把
同一批 `work/<场>/events.json` 用**三种口径**各打一遍分：

| 口径 | 规则 | 回答 |
|---|---|---|
| 官方 | 原项目 `tools/evaluate.py` 裁判：`truth.tolerance=0.2s` 行锚定；剔除 `deleted.json` + 比赛间隙球 | 「过不过现行验收门」（**最偏 HSV**，是下界） |
| 对称 | 每条臂用**自己的**事件时刻 ±0.5s 双向 1:1 配对 | 「看没看见 / 判没判出来」（不再要求落回 HSV 那一行） |
| 容差扫描 | 把时刻偏差扣掉，扫 W=0.2→3.0s（最邻近 1:1） | 「扣掉时刻因素后，检出/判定能力本身如何」 |

**三种口径的分母/容差/剔除规则都不同，数字不可互相搬运。**

```
# 只出报告（work\ 已有产物）：默认读本项目 work\、7 场标准集
.venv\Scripts\python scripts\eval_report.py

# 一条命令跑闭环：逐个场次跑检测（默认 YOLO）→ 出报告
.venv\Scripts\python scripts\run_eval.py

# A/B 对照：两条臂 = 两个 work 根目录（例如 YOLO 版 vs HSV 版各跑一遍）
.venv\Scripts\python scripts\eval_report.py --arm yolo=work_yolo --arm hsv=work_hsv
```

- 报告落在 `reports/EVAL_<tag>.md`（+`.json`，被 git 忽略，可再生）。
- `run_eval.py` 需要标定：优先读 `--calib-from\<场>\calibration.json`
  （默认 = `--out-work`）；**缺标定时自动从 `truth/<场>.json` 的 `calib_key`
  重建单段标定**（无参考帧 → 不做位移校正，多段标定的场次请显式给
  `--calib-from`）。**视频目录必须自己指定**：`--video-dir <你的视频目录>`
  （脚本里的默认值是作者本机的路径，在你机器上不存在）。
- 本套件**只依赖本项目内**的 `tools/evaluate.py` 与 `truth/`，不 import `bbh`、
  也不碰任何外部工程。

## 常见问题

- **上传视频报"无法打开视频"（Permission denied）**：大文件（几百 MB 以上）走浏览器
  上传易被占用/未收尾。长视频请用「⚙ 标定设置」页的「填本机路径」入口，不要上传。
- **上传视频报"无法打开视频"（其他）**：部分手机编码（AV1、某些 HDR 等）OpenCV 解不了。
  「⚙ 标定设置」页抽帧会自动退回 ffmpeg；错误信息会附带 ffmpeg 探测输出，把它反馈给开发者即可定位。
- **剪辑台检测前长时间显示"正在转码"**：同上，检测用不了原始编码时会先转成
  H.264 副本（`work/<视频名>/det-source.mp4`，只转一次，之后复用），长视频首次较慢属正常。

## 打包成 exe

本仓库**暂未接打包**。作者另有一个独立的打包工程（PyInstaller 便携绿色包，
不在本仓库内）；本项目若要出绿色包，
需要另立一个打包工程——注意 YOLO 侧要一并打进 torch / ultralytics 与
`bbh/weights/best.pt`，体积与构建方式都和原工程不同，不能直接复用。
