# 方案：单条视频生成（基于勾选片段逐条出片）（方案稿，未动代码）

- 日期：2026-10-21
- 前置：同日 grill-me 澄清会，十条裁定已定（§1）
- 需求池：**R-023**
- 结论：**可做，改动集中在"生成层加一个 output 分支 + 入口合并"，不碰判定层、不碰渲染核心算法**

---

## 0. 结论先行（四句话）

1. **能力增量很小，入口改造才是主体**：单条出片在现有代码里几乎现成（`build_vertical` / `build_highlight` 都接受 1 个片段），真正要写的是"循环 + 命名 + 去重 + 进度"，约 120 行；而"三个入口合并成一个"要动前端弹窗结构 + 后端 choices 契约 + e2e 断言。
   > **自查后补充（见 §2.6）**：能力虽小，但有 **4 条 P0 若不先修，单条模式直接跑不通或把按钮卡死**——合集项单点字符串比对、`open_gen_dialog` 撞 gradio 返回值契约、横屏异常裸穿透杀生成器、进度无 pct 通道。
2. **渲染核心一行不改**：逐球调用现有函数 N 次，**不动** `vrender.build_vertical`（856 行、字节契约）和 `editor.build_highlight`。唯一动它是为了省一次无用的白闪渲染（D2，已给等价性论证）。
3. **最大风险不是功能，是回归面**：横/竖两条既有交付链换入口，`tests/e2e/edit_bay.spec.mjs` 有 5 处断言钉死在"两个按钮"上（`:949,951,985,987,1212`），必须同步改，并用**成品 md5 对拍**证明渲染结果没变。
4. **必须实测一个数字**：竖屏单球渲染耗时（决定 N=30 时用户要等多久）。**已实测：14.99s/球 ⇒ 30 球约 7.5 分钟**（1080p 源）。这个量级下不做并行——并行要动 `vclips` 目录清理逻辑，风险远大于收益。

### 2.4 前端 · `GenDialog.vue`（改动最大的一处）

- **选择态顶部加两组必选**（`el-radio-group`，无初始值）：画幅 `横屏直切 / 竖屏运镜`；输出 `一条集锦 / 逐球各出一条`。
- **标题与提示按 4 组合出**（4 套 title + tip 常量），现有两句 `VERT_TIP`/`HORI_TIP` 保留复用，单条模式各加一句"逐球各出一条、命名 single-…"。
- **拉清单的时机**：打开弹窗时拉一次；**画幅/输出变化时重拉**（`stats` 前缀依赖画幅，`allLabel` 依赖输出模式）。
- **切模式的选择重映射**（关键）：新一次响应回来后，把旧 `pick` 里"等于旧 `allLabel` 的项"换成新 `allLabel`，其余标签项字符串不变直接保留。
- **确定按钮三重门**：`:disabled="!vertical || !output || !pick.length || running"`；缺项时 `title` 说明缺什么。
- **结果列表**：N 行时 `max-height: 40vh; overflow: auto`（其余不动，`videos[].url` 照旧逐行在线预览）。

### 2.5 三个必须写进代码注释的陷阱

1. **`summaryMd` 是隐式契约**：`_gen_result`（`api_gen.py:220-233`）按 `· ` 前缀 + ` → ` 分隔反解 `(item, 文件名)`，并靠 `os.path.exists` 判定真假。单条模式的行必须仍是 `· {item} → {basename}`（item 写成「标签 01:23.4」）。**改格式 = 界面显示"生成成功、清单为空"**。
2. **合集项是"勾选值字符串"本身**：切输出模式时它的展示文案要变（集锦 ↔ 逐球各出一条），如果直接当 key，切模式就丢勾选。**必须靠后端回的 `allLabel` 做重映射**，不能靠前端硬编码字符串。
3. **`anyJobRunning` 期间新按钮也要 disabled**：现在四个入口各自写了 `:disabled`，合并成一个后只留一处，别漏——漏了会在检测/回扫跑着的时候开出弹窗，抢同一批 sidecar。

### 2.6 自查修订：11 条必须并入的实现约束（2026-10-21 自审）

> 这一节是方案成稿后逐条核代码查出来的，**优先级高于上文**；冲突以上文被本节修正的写法为准。

#### P0 · 不改就跑不通 / 把按钮卡死

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| P0-1 | **合集项比对是单点字符串相等**：单条模式若给合集换新文案（"…逐球各出一条"），`gen_selected` 认不出它是合集，会当成标签名去筛 → 0 行 → 整项"无勾选进球"跳过 | `app.py:1370` `tag = "" if item == GEN_ALL_LABEL else item`；`GEN_ALL_LABEL` 定义在 `:1280`，另在 `:1342,1345,2314,2315` 使用 | 新增 `GEN_ALL_LABEL_SINGLE` + `_is_all_item(item)` 白名单判定；`_picked_rows` 内统一用它。**禁止**再写裸 `==` 比较 |
| P0-2 | **给 `open_gen_dialog` 加返回值会撞 gradio 契约** | gradio `outputs` 4 项（`app.py:2394-2401`） | 见 §2.1 已修正行：改由 API 层算 `allLabel`，函数签名/返回结构不动 |
| P0-3 | **横屏渲染失败是裸异常**：`generate_highlight` 只在竖屏分支把 `RuntimeError/ValueError` 转成 `gr.Error`，横屏 `editor.build_highlight` 抛的异常直接穿透；而 `gen_selected` 只 `except gr.Error` → **生成器中途死亡、按钮永久卡灰**。集锦模式今天就有这个洞，单条循环把触发概率放大 N 倍 | `app.py:2096-2106`（只有 vertical 有 try）；`:1373` 只 catch `gr.Error` | `generate_singles` 内层 `except Exception` 全兜 → 记 skipped；**顺手修集锦横屏分支的同类洞**（补 try→`gr.Error`），但要单独一行注释标明"附修" |
| P0-4 | **进度百分比没有通道**：`gen_selected` 的 yield 是 6 元组（gradio 契约），没有 pct 位；`_drive` 只转发 `msg` | `api_gen.py:73-82`；`jobs.py:54` `report(msg=,pct=,found=)` | `gen_selected(..., on_progress=None)` 可选回调，单条循环里 `on_progress(k, n)`；`api_gen.gen()` 接到 `report(pct=…)`。**不解析文案算百分比**（那会成为第二份格式契约） |

#### P1 · 实现陷阱（不修就静默出错）

| # | 陷阱 | 实证 / 原因 | 修法 |
|---|---|---|---|
| P1-1 | **`out_name` 必须带 `.mp4` 传入** | `build_vertical:847` / `build_highlight:138` 都是 `safe_filename(os.path.splitext(out_name)[0])`。实测：`splitext('single-竖-张三-01m23.4s')` → `'single-竖-张三-01m23'`，**`.4s` 被吃掉** → 同一分钟内的两个球撞名、后者覆盖前者（静默丢片） | 传 `single-竖-张三-01m23.4s.mp4`（带后缀）；命名函数返回时恒带 `.mp4`，并加单测钉死 |
| P1-2 | **Vue Boolean prop 传 null 会被归一** | `GenDialog.vue:16` `vertical: Boolean` | 弹窗内改用字符串枚举 `orient: "h"\|"v"\|null`、`output: "reel"\|"single"\|null`，只在发请求时转 `vertical` 布尔 |
| P1-3 | **切模式重拉清单的"初次口径"未定**：打开时两项都没选，但 choices 的合集文案依赖 output | — | 初次打开按 `reel` 口径拉（= 现状行为），用户切到 single 再重拉 + 重映射；重拉必须复用现有守卫 `job.phase !== "idle"` 不重拉 |
| P1-4 | **横屏单条要自己夹上界**：`build_highlight` 内部不做 clamp，clamp 在 `plan_clips(settings, duration)` 里 | `editor.py:33-39,124-143` | 循环外读一次 `events.json` 取 `duration`，自己 `min(duration, t+after)` |
| P1-5 | **`item` 语义两模式不同**：集锦模式 = 勾选项名；单条模式 = 「标签 时刻」 | `_gen_result:220-233` 只当展示串用 | 允许，但必须在 `_gen_result` 与前端注释写明"item 是展示串不是 key"，防止以后有人拿它做去重/匹配 |

## 4. 风险与回退

| 风险 | 影响面 | 处置 |
|---|---|---|
| **入口合并是回归面最大的一项** | 所有日常出片路径 | 渲染层不动 + md5 对拍兜底；前端单点回退（恢复 button-group）不影响后端 |

| 单条与集锦同目录 | 发布时选错文件 | `single-` / `highlight-` 前缀已区分；不上子目录是你的裁定 |
| 同名覆盖 + 不跳过已存在 | 重复渲染浪费机时 | 已裁定；换来"改前后秒一定能重出" |

- 只回前端 → 恢复两个按钮，后端 `output` 缺省 `"reel"`，功能等价于今天。
- 全回 → 单次 `git revert`（改动集中在 5 个文件 + 1 个 build 产物提交）。
