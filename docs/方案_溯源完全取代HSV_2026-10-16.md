# 方案 · 溯源完全取代 HSV（球检测全 YOLO 化）

- 日期：2026-10-16
- 目标（用户原话）：**我们的目标就是完全取代 HSV**——把出手人溯源链里残存的 HSV 检球全部换成 YOLO，最终退役点选球色/HSV 滑块，消灭双检测器维护面。
- 性质：**本文档仅为方案，未经用户确认不动任何代码。**
- ⚠ 协同边界：shooter（A2/A3）正由另一 Claude Code 会话推进（2026-10-15 22:42 刚提交 person 框裁剪 `a814f67`）。本方案 Phase 0 为只读诊断不冲突；**Phase 1 起要动 shooter.py，实施前须用户裁定由哪个会话执行。**

## 0 结论先行

1. **方向可行，但必须分阶段、带数据门推进**。HSV 在溯源里共 4 个消费点（§2），全部可被 YOLO 替换且下游几何链无需重写——链本来就是多候选设计（每帧最多收 3 块）。
2. **必须正面回应历史否定结论**（L1 诊断 2026-10-14 §4 曾实测"不建议 A2 换 YOLO"）。本方案 §3 给出为何当时否决、为何现在重开：当时是**无门控的原始检出 × 24 个失败窗口**；如今有了 person 框排斥、尺寸门、正常窗口干净弧线三个新证据。
3. **诚实定位：本目标不是提质，是去 HSV 化**。YOLO 未必更准（收益上限仍是那 3.6% 溯源真错）。**验收口径（2026-10-16 用户裁定：选项②「容忍式」——去 HSV 化优先，可容忍小幅劣化）**：具体容忍数字见 §4 Phase 0 的门槛表；另设**无条件灾难红线**（任一触发即终局维持 HSV）+ 一轮调参复活机会。
4. 完全退役分四步：**Phase 0 对拍数据门 → Phase 1 溯源 YOLO 化（开关制）→ Phase 2 标定向导瘦身（R-016 重启）→ 可选 Phase 3 删除 HSV 全部代码路径**。每阶段独立可停、可回退。

## 1 竞品调研：不靠颜色，他们怎么做球检测/追踪

### 1.1 已有竞品调研库结论（`竞品调研/`）

| 项目 | 球怎么做 | 与本方案的关联 |
|---|---|---|
| abdullahtarek/basketball_analysis | YOLO 逐帧、**每帧只取最高 conf 球框**；`remove_wrong_detections`：与上一好框距离超 25px×帧间距判假阳性删除（链式推进）；漏检线性插值 | 其"链式距离门"≈我们 `_kill_statics`+单调逼近的朴素版，证明后处理是 YOLO 球检的标配而非 HSV 特供 |
| NUSTemple/basketball-shot-clipper | YOLO(COCO)+筐周 ROI 目击几何+GBM 过滤；**纯人工归人（ByteTrack+HSV 聚类原型已否）** | 竞品里最接近我们架构者，**完全无 HSV 球检** |
| vincenzonetti/CVproject | 双专用模型（ball/players）+ BoT-SORT；同类多检**只留最高 conf** | 多候选→单选的极简策略 |
| hetuvpatel/BasketVision | YOLOv8 + ByteTrack 球轨迹平滑，~9.6ms/图 | 球多目标跟踪的通用做法 |

### 1.2 本次 Web 调研新增

| 项目 | 关键做法 | 可借鉴 |
|---|---|---|
| **JadenS180/basketball-shot-tracker**（2026-07，最接近我们的"固定机位小球"场景） | ① **imgsz 640→1280：球检出 25.6%→96%**（自训三类 ball/rim/human，conf 0.05）；② **person 框排斥**：球候选与 person 框重叠则拒绝（只用于筐上宽区跟踪）；③ **表观尺寸门**：球在弧顶/穿越点的大小 vs 该深度应有大小，近景大球判假；④ 路径陡度判别 | ②③ 是治"YOLO 静态误检/人身误检"的直接药方，成本极低 |
| Zaraius/basbetball-tracker | HSV 色掩码被实测放弃（"impossible task"：光照/阴影/同色背景）；YOLOv11n 域内微调（仅 50 帧标注）即稳定 | 反证 HSV 路线脆弱；域内微调数据量门槛不高（我们已有 5545 球框标注） |

### 1.3 调研小结

- **没有任何一家活跃项目在固定机位篮球场景继续用 HSV 球检**；HSV 时代已结束（呼应 10-15 结论：竞品调研 20 仓零家做球颜色标定）。
- 竞品处理"YOLO 球检噪声"的三件套：**conf/尺寸门 + 链式距离/静块剔除 + person 框排斥**。前一件我们已有等价物；第二件几何链自带；第三件经 grill 裁定**不进生产设计**（A2 窗口球在持球人手上会杀真阳性），仅作 Phase 0 可选对照臂。
- 跟踪器（ByteTrack/BoT-SORT）对**球**不是必需——单球窗口内"就近+门控"足够（abdullahtarek 球都不用 tracker）。

## 3 为何重开"YOLO 替 HSV"：对 L1 否决结论的正面回应

L1 诊断（2026-10-14 §4）实测否决的**适用范围**要划清：

| 当时 | 现在 |
|---|---|
| 测试对象=**24 个失败窗口**（spot/iv/low，HSV 的最差场景） | A2 日常面对的是**正常进球窗口**——全弧 Spike（10-15）实测同款 best.pt@1024 在正常窗口给出**干净单抛物线**（conf 0.45~0.77，单球 0.5~2.4s） |
| **无门控原始检出**直接看噪声（conf≥0.10，多候选、conf 0.52 静块） | 竞品三件套现成：①尺寸门（球径≈0.22×筐宽² 面积当量，框宽可换算）②链式静块剔除（**我们几何链自带**）③person 框排斥（模型已随包，**经 B 裁定仅作 Phase 0 对照臂，不进生产设计**） |
| 结论"换检出器=重写整条几何链" | **几何链不用重写**：链输入本就是多候选 `BallPos` 流（HSV 每帧也收 3 块），换检出器=换"候选从哪来"，§2 四个点的调用面都是"帧→候选列表" |
| 隐含前提：球检模型=通用 COCO | 我们是**自训域内 best.pt**（5545 球框标注）；reID 专项的 51.3% 召回黑数字来自通用域模型，不适用 |

**但必须保留 L1 的教训**：远景 YOLO 原始噪声确实大，Phase 0 必须实测我们的失败窗口在加了三件套后能恢复到什么程度——**这是数据门存在的意义**。

## 4 方案（分阶段，每阶段独立验收、独立回退）

### Phase 0 —— 对拍数据门（只读诊断，~半天，先跑这个）

**做什么**：新脚本 `诊断/2026-10-16-HSV退役/phase0_a2ab.py`，不改任何生产代码：

1. 取 10 场全部进球事件（`work/*/shooters.json`，3099 球），每球 6s 窗（隔 2 帧）跑 best.pt@1024（classes=[0]），A/B/C 三口径：
   - A=现状 HSV（复用现有 shooters.json，不重跑）；
   - B=YOLO+门控（尺寸门=框面积当量 0.10~0.35×筐宽²；conf 门 0.05/0.15/0.25 离线套用——**推理只跑一遍 conf 0.05 收全量检出，高 conf 是低 conf 的子集，三档门直接对缓存套用，不重复推理**）；
   - C=B 变体（imgsz 1280，仅当 B 球召回不足时）。
2. 检出流喂进**现有** `trace_release` 纯函数链 → 产出每球 `TraceResult`，与现状对比：**档位迁移矩阵**（high/review/low）、spot_bad 率、间隔离群率。
3. **truth 出手人命中率测法**：用 YOLO 臂的新 `release_xy` 重跑 `person.pick_person`（球锚同臂口径换 YOLO 检出）→ 归属人对比 `truth/*.json` 943 条标注；A 臂命中率同法同步测出作基线。

**验收门（2026-10-16 用户裁定数字，容忍口径）**：

| 指标 | 现值（HSV） | 容忍线（YOLO） |
|---|---|---|
| 溯源真错率（spot_bad+离群+low） | 3.6% | **≤ 4.5%** |
| high 档占比 | 70.8% | **≥ 68.8%**（降 ≤2pct） |
| truth 出手人命中率（943 标注） | 现基线（Phase 0 同步测出） | **降 ≤1pct** |

**无条件灾难红线**（容忍口径也不许过，任一触发即终局维持 HSV）：①某场 ⚪ 未溯源率 >5%（对照 09-19_1 崩场先例）；②truth 命中率降幅 >3pct；③出现 HSV 没有的新故障形态（如系统性把出手点标到同一静块）。

**调参复活**：不过容忍线时允许一轮（conf / imgsz 1280 / 门参数任调一项后复测一次），仍不过即终局。

**对拍口径补充（grill 审查修正，2026-10-16）**：
- **conf 门不承担杀静块的任务**——生产主检测 conf=0.03 而静块实测 conf 0.45~0.52，conf 只调召回-噪声平衡；静块由尺寸门+`_kill_statics` 链杀。
- **person 框排斥默认关闭**（B 分支裁定）：A2 窗口开局球在出手人手上，排斥会杀真阳性（JadenS180 也只在筐上宽区用）；误检交给链。Phase 0 保留"+person 排斥"作可选对照组，用数据说话。
- **分场明细必须出**（不只看 10 场合计），重点看 09-04_1（HSV 最差场）不崩。
- **失败窗口专项复验**：L1 那 24 个失败窗口不作门（HSV 本来就失败），但要确认**正常球不新增失败**。

**产出**：`诊断/.../Phase0结论.md` + 对照网格图（重点看失败窗口在 YOLO 下的表现）。

### Phase 1 —— 溯源 YOLO 化（开关制，~1 天）

**改哪些文件**：

| 文件 | 改动 |
|---|---|
| 新增 `bbh/ball_yolo.py`（~120 行） | YOLO→`BallPos` 适配层：`detect_points(frame, hoop_w) -> list[BallPos]`，内置 conf 门/尺寸门/筐带排除；模型复用 `bbh/weights/best.pt`（进程内单例，与主检测共享）。**已核实 `trace_release` 链只消费 t/x/y 不读 area**——框面积仅填字段；HSV 侧的填充率/S 中位门是轮廓特有，YOLO 无对应物也不需要（复检 2026-10-16） |
| `bbh/shooter.py` | §2 四个消费点各加分支：`scan_release_window`/`_rescan_release`/`_ball_near` 按 `BBH_SHOOTER_SCAN=yolo|hsv`（默认 **hsv**，数据门过+验收后再翻转默认）；`_rescan_release` 三连硬门、`_ball_near` 就近规则**原样保留** |
| `bbh/person.py` | `ball_anchor` 加 yolo 分支（同一适配层） |
| `bbh/shooter.py` 缓存身份 | 默认翻 yolo 时 `SHOOTER_VERSION` 6→7；过渡期开关名并入身份键（hsv/yolo 缓存不混、来回切各重扫一次）；异常自动降级回 HSV（照抄 `BBH_PERSON` 降级范式，不崩） |

**三条设计裁定（grill 审查 2026-10-16，C/B/D 分支）**：
1. **推理形态（C）**：四个消费点一律**整帧推理（imgsz 1024）→ 坐标域内筛候选**——`detector_yolo.py:63` 注明"训练即此构图"=整帧，crop 推理有分布偏移；四点帧量小（A2 ~90 帧/球、GIF 数十帧、球锚 1~2 帧），整帧成本付得起。
2. **person 框排斥（B）**：A2 回扫**不用**（窗口开局球在出手人手上，排斥杀真阳性；JadenS180 也只在筐上宽区用）；A3 GIF 跟球同理不用。只作为 Phase 0 可选对照臂。
3. **缓存与开关（D）**：见上表身份键设计；开关来回切各重扫一次（回退是罕见操作，可接受）。

**验收**：①全套 pytest（heavy 分批）；②真机重扫 2 场（09-04_1 最差场 + 一场正常场）， shooters.json 与 Phase 0 结论一致；③开关切回 hsv 结果与现档完全一致（回归零损）。

**风险与回退**：风险=远景漏检→⚪/review 增多（表现为溯源覆盖率降，可见可量化）、新误检劫持链（三连门+_kill_statics 兜底，Phase 0 先验）；回退=环境变量切回 hsv，指纹保证缓存不混。

### Phase 2 —— 标定向导瘦身（R-016 重启，~半天）

Phase 1 稳定跑过 ≥3 场后：点选球色/HSV 滑块退役（向导 4 步→2 步：拖筐框→YOLO 验证），`hsv_low/high` 字段保留但只填默认值（hsv 回退开关的种子）；前端 `CalibWizard/BuildPanel/HsvPanel` 文案同步。**即 R-016 原方案在数据门保障下落地。**

### Phase 3 ——（可选，最后）HSV 代码全退役

删 `detector_switch` hsv 模式对照版、`run_app_hsv.bat`、shooter HSV 分支、conftest 强制 hsv 改造（合成测试视频改用 yolo 或离线 fixture）。纯清理、无功能收益，**建议放最后甚至不做**——hsv 回退开关留着零成本。

## 5 成本与影响面

- **推理成本**：`SCAN_STEP=2` → ~90 帧/球；13ms/帧（RTX 3050@1024）≈ **1.2s/球**（batch32 ~0.9s）；310 球/场 ≈ 首扫 **+6min/场**（HSV 现值 ~0.3s/球），缓存后二次零成本。可接受；如嫌重可只对 high/review 球开 yolo。
- **影响面**：Phase 1 只动溯源读帧侧，**不碰**：进球判定链（goal_decider）、主检测、vrender、web 层、剪辑台。person 框裁剪（a814f67）零冲突（球锚换了检出器，归属阶梯不动）。
- **与另一会话协同**：Phase 0 只读无冲突；Phase 1 动 shooter.py **必须先裁定执行者**（本会话接管 / 交给 shooter 会话，方案文档可直接移交）。
