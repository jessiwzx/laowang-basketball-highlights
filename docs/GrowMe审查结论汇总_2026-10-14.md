## 0 一句话总纲

> **v1 是"由调研 + 代码推出"的技术机会清单，不是"由痛点推出"的待办清单。**经 GrowMe 逐轮追问，(1) v1 的主线（深化 YOLO 检出）被**证据链否定并关闭**；(2) 真实痛点收敛为**归人/复核太耗人工**，且其**全自动化解法已被证明不可达**；(3) 唯一站得住的杠杆是**交互降本（L3）**，其次可选**复核降本（L4）**。

## 1 评审起点：v1 是什么、错在哪

v1（`优化方案_竞品对比与可优化项_2026-10-14.md`）把竞品调研与本项目实现逐层对比，产出 O1~O8 八项可优化项，并给出优先级：**O1（A2/A3 换 YOLO）、O2（竖屏持球链）列 P0**。

GrowMe 审查判定：**方向反了。** 它是**从"调研说了什么 + 代码还能改什么"倒推出来的机会清单**，而非从"用户真实遇到什么痛"推出。

## 2 审查抓到的 4 个实质问题

| # | 问题 | 具体 |
|---|---|---|
| **①** | **优先级倒挂（最大）** | v1 把 O1/O2 列 P0 并标"研究背书最实"——**属误引**：`竞品调研报告` 原文把"YOLO 检出替换"列为**观察项（不急）**，理由写明"瓶颈在判定不在检出，故低优先"。同时把**零成本立竿见影**的 O3（归人降本）和"带病发货"的 O6（09-19 崩场查全 36%）压到了 P1。 |
| **②** | **O1 核心假设未验证** | A1 换 YOLO 成功是在**筐周近景**；A2 回扫（三分线外）、A3 跟球（运球段）都是**远景几像素小球**，**域不同**，自训权重在远景的 ball 判别力**从未测过**。更关键：A2/A3 的痛点本质是**"球的身份"**（区分球 vs 同色人体/篮筐），**不是"能否检出"**——换检出器未必解决。 |
| **③** | **O2 证据偏乐观，且是重开挂起坑** | 所引 spike"层1 跑通"只证明**"每球归到了正确 tracklet"**，**不等于** lead 段逐帧跟人的运镜观感；且该文档自述"层1 正确率**无法单独验证**（无 tracklet 真值）"。O2 本质是重开一个**已被五轮实测证伪、2026-10-10 才挂起**的问题，还要新增 person 检测 + 跟踪整套依赖。 |
| **④** | **O1/O2 是同一问题的两面** | 两者根因都是**"远景下目标（球/人）的语义身份"**，需同一能力（远景检测），拆成两项=重复投入。 |

**次要问题**：全篇无量化（缺函数级/工时/依赖估算）；混淆"调研原话"与"我的推论"；O4 漏斗计数可能是**伪需求**（判定已 v18 定稿）；O7"筐周 ROI 二次精检"与 A1 现行"整帧推理"设计**相矛盾**。

## 3 逐轮追问的三个转折

### 转折一：优先级重排（v1 内部修正）
O1 从 P0 **降为"Spike 门控"**、O2 从 P0 **降为"待产品取舍"**；O3/O6 **升 P0**。

### 转折二：连"重排后的 P0"也被否——**没有一项"必须做"**
用户追问"每一项真的有必要吗"。逐项诚实裁决：

| 项 | 诚实裁决 |
|---|---|
| O1 A2/A3 换 YOLO | **低**（研究原判观察项；真问题在"身份"不在"检出"；可能白做） |
| O2 竖屏 lead 持球链 | **低-中**（观感功能 + 重开挂起坑 + 新依赖） |
| O3 归人降本 | **取决于使用频率** |
| O6 崩场诊断 | **低**（可把该场从统计剔除） |
| D2① bug | **低**（只影响"点流重放"效率，触发条件窄） |
| O4/O5/O7/O8 | **低**（判定已 v18 定稿，属锦上添花） |

→ **v1 的真实性质被揭穿：一份"技术机会清单"，不是"待办清单"。优化的正确起点是痛点，不是"可做的事"。**

### 转折三：痛点锁定 → 自动化被证死
用户确认真实痛点 = **归人/复核太耗人工**（调研痛点②），并表达理想是**"自动识别出手人 + 自动归类"**。GrowMe 给出**残酷但关键的事实**：

- **层2｜外观自动认人**：已**证伪**——OSNet 在远景便装上同人/异人**余弦完全重叠（0.701 vs 0.700）**，对拍命中率仅 **11~14%**。**这条路死了。**
- **层1｜持球链几何**：看似可行，实测 **107 个 tracklet 对应 109 个球——基本一球一段，无任何归并**（按"每球出手前 8s"开窗，同人投 12 次=12 个窗口）。
  > 要归并成"17 个人"必须靠层2，而层2 死了；理论上"全片连续跟踪"可归并，但 SportsMOT 证明篮球全片跟踪 + 无外观时 ID 漂移最严重，不现实。

→ **结论：当前技术下，归人人工没有可靠的自动化解法。** 唯一真实杠杆是**交互降本**——把"每球一次次操作"变快，而不是把"球的条数"变少。

## 4 三条硬结论（评审的最终判断）

### 结论 A：判定层已到天花板，**判定提升线全部关闭**
调研的 P0/P1/P2（反弹拒绝、fill_ratio、静止众数簇、GBM 篮网特征、CNN 仲裁、在线 ReID…）已在四场/五场 truth 上**全线证伪**，且多数获业界旁证。**不再投入**（重启条件见 §5）。

### 结论 B：优先级主体倒转——"省人力 + 补质量" > "深化 YOLO"
研究最终指向的是 **"判定已到头 → 省人力 + 补质量"**，而非"继续深化检出"。零成本/确定性收益的项（归人交互、复核降本）应排在重依赖项（YOLO 检出替换、person 跟踪）之前。

### 结论 C：L1（换/混 YOLO 检出球）**实测否定、关闭**（见 §6）
"出手人识别不准"经诊断，**主体是呈现形态**（广角小脸），**不是溯源算法故障**；换检出器**没有干净收益**。

## 6 L1 诊断结论（已执行，2026-10-14）

**数据**：上游 `D:\claude code\视频剪辑\work\*`（10 场 `shooters.json`，shooter_ver 6；**两仓 `bbh/shooter.py` 完全相同**）+ 943 条 truth 出手人标注。

| 维度 | 结果 |
|---|---|
| 自动指标 | 3099 球溯源，**⚪未溯源仅 8（0.26%）**；合理区间隔 **99.1%**；标注 943 条 99.9% 有溯源 → **Phase 1 的 ≥80% 门是过的** |
| 真·算法错 | **≈3.6%**：`spot_bad` 86（定位失效→全场图黄标）+ 间隔离群 27（crop 裁到顶棚/暗墙）+ `low` 8 + `extrap` 43；最差场 **09-04_1** |
| "认不出/十字不准" | **非算法错，是呈现形态**：crop 是**广角半场**（人物仅占一部分、常同框 3~4 人），远景**人脸仅十几像素、物理不可辨** |
| **判决性实验：远景 YOLO 替 HSV** | **否定**——24 个失败窗口跑自训 `best.pt`，能读到的 20 例 YOLO **每帧给出多于一个"球"候选**（08-28_1 五例 60 帧检出 69~91 次）+ **高置信静态误检**（固定点 conf 0.52）；08-21_1 四例视频 seek 读不到帧 |
| GIF 呈现 | 翻遍 20 仓 + 35 份笔记：**没有任何竞品提供更优的"呈现形式"**（reborncd/ShotCut/hoopclips 全是**交互**）→ **维持** |

**裁决**：`L1（A2 换/混 YOLO 检出球）` **关闭**；若仍要修那 3.6%，唯一方向是 **COCO person 框吸附裁剪**（需新增通用 person 模型，只改"看得清"、不改"认得清"）。
