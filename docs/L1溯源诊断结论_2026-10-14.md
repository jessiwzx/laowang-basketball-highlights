# L1 · 出手人溯源 诊断结论

- 日期：2026-10-14
- 触发：`优化方案_v2_痛点驱动_2026-10-14.md` 待确认项 1「先诊断 L1 再定」——用户报「出手人识别不准=①拍错人+②认不出+③十字不准」。
- 数据：`D:\claude code\视频剪辑\work\*`（10 场 `shooters.json`，`shooter_ver=6`，即当前两仓**完全相同**的 `bbh/shooter.py` 的输出）+ `truth/*.json` 的 `shooters` 标注（943 条）。

## 0 结论先行

1. **溯源算法本身没有系统性故障**：10 场 3099 球溯源，⚪未溯源仅 8 球（0.26%），出手→进球间隔落在合理区（0.3~4.0s）的占 **99.1%**。当年 Phase 1 的 ≥80% 缩略图有效率门是**过**的。
2. **用户所见「不准」的真实构成**：
   - **真·算法错 ≈ 3.6%**（顶棚静块劫持 → 裁到顶棚；定位失效 → 全场图兜底）——这才对应「①拍错人」。
   - **「②认不出 + ③十字不准」的主体不是算法错，是呈现形态**：裁剪是**广角半场**（人物只占画面一部分，人多时同框 3~4 人），远景人脸仅十几像素、**不可辨**；十字落在出手点（≈肩高）在广角下并不醒目。
3. **「A2 换/混 YOLO 检出球」不建议做**——三条证据都指向不划算：
   - 收益上限就是那 3.6%，且其中多数是**轨迹被静块劫持**，不是"检不到球"；
   - **远景 YOLO 实测噪声大**（见 §4）：失败窗口里 YOLO 每帧给出**多于一个"球"候选**，还有高置信**静态误检**（固定点 conf 0.52），换上去等于重写整条几何链；
   - 设计文档 `2026-08-23-shooter-attribution-design.md` 早已定调「**咱机位球仅 5-10px，球检测继续用自家 HSV**；YOLO 的定位是 person 框」。（注：该结论针对 COCO 通用模型；fork 自训 `best.pt` 在**筐周近景**能检到球=A1 成立，但**远景**经本次实测并不可靠。）
4. **GIF 呈现形式：维持**——竞品调研里**没有任何竞品提供更优的"呈现形式"**（见 §5），与用户判断一致「GIF 形式不坏，坏在内容」。可改善的只有那 3.6% 的内容错，而非形式。

> 一句话：**L1 已达到"能用"水平（96.4% 正确），瓶颈不在检出器，而在"远景素材本身就认不清人"。** 继续投入 L1 的边际收益极低。

## 3 呈现形态：这才是「认不出 / 十字不准」的主因

- 源视频 1280×720；静态缩略图 ≈ **275×413**（≈1/3 宽 × 56% 高），GIF 更宽（如 398×640）。
- 裁剪框由"筐宽换算"推出，是**场上尺度**的一段，不是人形特写——**人物只占画面一部分，且同框常有 2~4 人**。
- 远景机位下**人脸仅十几像素，本质不可辨**（设计文档早已记录"脸仅 ~12×14px"）。
- 证据图：`诊断/2026-10-14-L1溯源/GIF逐帧样例.png`（两个 GIF 全帧铺开）。

**推论**：用户"盯 GIF 也认不出这是谁"是**素材分辨率的物理极限**，任何检出器都改不了；"十字不准"在宽景下也因参照物不足而不显眼。

## 4 判决性实测：远景 YOLO 能不能替 HSV？（不建议）

对 24 个失败窗口（spot/iv/low）跑自训 `bbh/weights/best.pt`（imgsz 1024、classes=[0] 球、conf≥0.10）：

| 结果 | 观察 |
|---|---|
| 08-21_1 的 4 例 | **视频 seek 读不到帧**（该文件本身问题），未测到 |
| 其余 20 例 | YOLO 都给出检出，但**唯一位置 4~25** → 混杂；08-28_1 五例 60 帧检出 **69~91 次**（每帧多于一个"球"候选） |
| 定点复看（08-28_1 13:13.8） | 存在 (576,308) 附近**连续 3 秒不动**的框，conf 0.45~0.52 = **静态误检** |

**结论**：远景 YOLO 的**原始**检出对"球 / 皮肤 / 头 / 静物"没有判别力，噪声比 HSV 更大；要用它必须把现有整条几何链（单调逼近、静点剔除、方向门控、抛物线外推…）**重写一遍**。**"换检出器"不是净收益。**

证据图：`诊断/2026-10-14-L1溯源/YOLO远景检出样例.png`。

## 5 「GIF 呈现 / 有没有更好的呈现方式」——调研结论

翻遍 `竞品调研/`（20 仓 + 35 份逐仓笔记），**没有任何竞品提供优于"缩略图墙 + GIF"的呈现形式**。与"呈现/复核体验"相关的全部落在**交互**，不是形式：

| 竞品 | 做法 | 归属 |
|---|---|---|
| reborncd/basketball-highlights | 归人页「**分配即自动跳下一个**」 | 交互 |
| diablofong/ShotCut | **数字键选人**（播放中按 1/2/3 录标记） | 交互 |
| amdslancelot/hoopclips | **焦点人模式**（先选人后跟踪，每人一次点选） | 交互 |

调研报告对出手人的定性结论（原话）：**"没有任何竞品解决野球场（无队服/无号码/同色系）自动归人；唯一不依赖外观的是持球链几何；短期立竿见影的是键盘化交互降本。"**
→ **呈现形式维持 GIF**；调研指向的杠杆是**交互**，不是呈现，更不是检出器。

## 6 裁决与下一步

| 项 | 裁决 | 理由 |
|---|---|---|
| **L1 · A2 换/混 YOLO 检出球** | ❌ **不做** | 收益上限 3.6%；远景 YOLO 检出噪声更大；设计文档已定调用 HSV |
| （若一定要修那 3.6%） | ⏸ 备选：**COCO person 框吸附裁剪** | 用通用 person 模型把裁剪**吸附并收紧到人**——可修"裁到顶棚/框到背景"，并让人物放大居中缓解"认不出"。**代价：新增通用 person 模型；只改"看得清"，不改"认得清"**；仓库现只有自训 ball/hoop 权重，无 person |
| **L2 · 呈现形式** | ➡ **维持 GIF** | 调研无更优形式；用户亦认可形式本身 |
| **L3 · 归人交互降本** | ✅ **建议做**（零模型、零风险） | 调研唯一正面结论；直击"归人/复核耗人工"这个真痛点 |
| L4 · 复核降本 | ➡ 可选 | 键盘 y/n + 档位过滤；HIGH_CONF 用户已定"保持现状" |

**和 v2 的差异**：v2 把 L1 列为"先诊断、Spike 门控"；本诊断给出**实测否定结论 → L1 关闭**。v1/v2 里"深化 YOLO"这条主线，到此证据链完整地**排除**了。
