# 方案 · YOLO 时代的篮球标定（竞品调研 + 分层实施）

- 日期：2026-10-15
- 性质：**调研结论 + 方案设计**，未动任何代码
- 背景：用户问"检测都换 YOLO 了，为什么标定还要点选、还能调 HSV 参数？"——上一轮已澄清标定产物两分（筐口矩形=几何锚定 / 球 HSV=溯源种子）。本方案回答下一问：**用 YOLO 的项目到底怎么做"标定"，我们该怎么演进。**

---

## 1 竞品调研：YOLO 系项目的"标定"到底怎么做

翻遍 `竞品调研/notes/` 中用 YOLO 做篮球检测的全部项目，**标定环节共四种形态**：

### 形态 A · 人工标筐（我们现状的同族）

**NUSTemple/basketball-shot-clipper**（与我们最可比：固定机位半场、筐小、追求进球判定）：
- **每视频一次人工拖框**存 `hoop_bbox_norm`，球检测用 COCO `yolov8l` 的 sports ball 类（零自训）；
- 其 `PLAN.md` 决策 11 **明确裁定过"不引入筐检测模型"**，理由两条：跨场地/机位/光线的**域风险** + **人工标定成本本来就极低**；
- ROI 从人工筐框外扩（水平 ±(0.6+1.5) 筐宽、上不设限、下 1.5 筐高），推理裁 ROI 省 8~10 倍像素。

> **旁证价值**：和我们架构最像、且**认真权衡过"要不要自动标筐"**的项目，结论是保留人工。我们不必为"还在点选"感到落后。

### 形态 B · 筐当检测类别（"动态筐"，替代标定）

- **griftt/ball-yolo**：自训 3 类（ball/rim/person），**逐帧同时检测球+筐，取最高置信 rim 框为基准**——"动态筐"防机位移；另一个脚本用**前 30 帧筐位置均值校准后固定**（=自动标定）。实测结论：**imgsz=1024 显著提升小筐检出**（640 整帧会把筐缩到 20~40px）；
- **OwlTing/AI_basketball_games_video_editor**：自训 YOLOv4 含 `basketball_hoop` 类，逐帧检测，**无任何标定环节**（转播画面筐大好检）；
- **isBre/Automated-Basketball-Highlights**：自训 YOLOv5s 检筐（430 张人工标筐训练）→ 筐心 crop → ResNet50 判 point/no-point。**筐定位交给检测器，标定转成了"标训练数据"**；
- **Shahzad-Khan9294**：两级 EfficientDet——第一级在前 300 帧内检测 net **自动定 ROI**（静态、全程不更新、无位移处理）。

### 形态 C · 学习型判据（标定消失：判据本身是学的）

- **johnxie301/Yolo_v8n_shooting_practice**：把"出手中/已离手/球近筐/进筐"**训练成检测类别**，事件侧只剩数帧+倒计时，无筐口几何、无标定；
- **Shahzad 的 "goal" 外观类** / **isBre 的 point 类**同理——筐口判据被"学进模型"。

### 形态 D · 模板匹配漂移修正（非 YOLO，但解决同一问题）

- **ture1235/goal_detect**：标定存 ROI 模板图，每 100 帧全网 `matchTemplate` 搜模板、**置信度 ≥0.75 才平移并刷新模板**（渐进式跟踪缓慢漂移）；
- **snowroll**：同族做法，实测 11 分钟漂移 +2→+13px 全程修正。

### 调研核心结论

1. **没有一家做"点选球颜色"式的球标定**——颜色/HSV 标定是 HSV 检测器时代的专属产物，YOLO 系项目的"球"要么自训类别要么 COCO sports ball；
2. **"标定"在 YOLO 时代只剩一件事：告诉系统筐在哪**——要么人工（形态 A，域风险最低），要么检测器代劳（形态 B/C，把域风险转嫁给训练数据）；
3. **形态 B 的关键工程参数**（若走自动定筐）：imgsz≥1024、前 N 帧均值校准后固定、逐帧重检需配时序平滑；
4. **形态 C 与我们的判定优势互斥**：我们的几何+网运动+网簇判定（查准 78~83%+）远强于竞品的"阶段当类别"，无需走 C。

## 2 我们的现状盘点（本轮代码核实）

| 事实 | 代码落点 | 含义 |
|---|---|---|
| **自训权重已有 hoop 类（class 1）且从未使用** | `detector_yolo.py:58,125` 只取 `classes=[0]`（ball） | 形态 B 的基础设施**已经在权重里闲置**——当初训练花了 6158 个筐框标注 |
| **hoop_rect 耦合 8 个模块** | `goal_decider.py`（CROSS_KILL_OFF ±0.45 语义直接锚定"标定余量 5%"）、`net_motion.py`（sidecar 指纹含 hoop，变了就作废重测）、`net_clusters.py`、`static_filter.py`、`detector.py`（ROI）、`vrender.py`、`pipeline.py` | **逐帧动态筐 = 判定几何随帧浮动 + 缓存体系重写**，是大动作，不是"换个来源" |
| 筐仅 33~65px | 7 场标定实测 | 自动定筐必须 imgsz=1024（现状已是），且需防"人头顶/灯"误检 |
| 球点选 HSV 范围的消费方只剩 shooter 种子 + HSV 对照 + 标定页预览 | `shooter.py:186,801`；`conftest.py` 强制 hsv | **shooter 正由另一会话重构**——若其新方案不再要 HSV 种子，球点选可整体退役 |
| 10+ 场现成人工标定 | `视频剪辑/work/*/calibration.json` | **自动定筐的验收基准是零成本的**：拿建议框和人工框对拍即可 |

## 3 方案：四层演进，推荐走 T1 + T2

### T1 · 修正标定页"验证失真"（= 需求池 R-013 的实施）｜小改，独立可先做

- **改什么**：标定向导第③步"生成并验证"的预览图从 HSV 命中（`overlay_preview`）改为 **YOLO 检出对照**（同一帧跑 `best.pt` classes=[0]，画检出框）；第④步 HSV 滑块区加一行说明"此参数仅作用于 HSV 对照版与出手人溯源色域种子，不影响 YOLO 主检测"。
- **不动什么**：标定流程、点选方式、`Calibration` 数据结构全部不变。
- **验收**：标定页预览的绿框 = 剪辑台实际检出的球（同帧对拍一致）。
- **风险**：低；纯展示层，可整体回退。

### T2 · 自动定筐建议（推荐的主方案）｜中改，Spike 先行

把标定从"**点筐口两端 + 点球 1~3 次**"简化为"**确认一个建议框**"：

- **流程**：向导抽帧后，后端抽 N 帧（跨标定段各抽）→ `best.pt` 跑 `classes=[1]`（hoop）imgsz=1024 → 按段取**中位框**（防单帧抖动/误检）→ 作为**建议筐框**预填进标定页 → 用户看一眼，微调或直接确认；**检测不到/多框歧义时回退现有点选流程**（人工永远兜底）。
- **为什么不动判定链**：建议框最终仍落成同一个人工确认的 `hoop_rect`——`goal_decider` 的 ±0.45 语义、网运动 sidecar、缓存指纹**全部零感知**。这是它与"动态筐"的本质区别。
- **Spike（先跑，只读零风险）**：写脚本对 10 场各抽 30~50 帧跑 hoop 检测，统计：检出率、单帧框与人工框的偏差分布（中心 px / 宽高 %）、误检形态（人头顶？灯？第二个筐？）、跨段差异。**用现成人工标定做真值，一次跑完就有 go/no-go 结论。**
- **验收标准（建议）**：≥90% 场次能给出唯一稳定建议框；建议框与人工框中心偏差 ≤ 0.15 筐宽、宽偏差 ≤ 15%；达不到就保持人工点选，T2 关闭。
- **风险**：小筐远景下 hoop 类召回未知（虽已训）；多筐/误检需中位数+段内一致性过滤兜底。

### T3 · 动态筐（逐帧重检替代标定 + ORB 配准）｜大动作，暂缓

- griftt 路线。收益：机位被碰自动跟随；代价：`goal_decider` 几何随帧浮动、`net_motion` sidecar 指纹、缓存体系全要重设计——**影响面 8 个模块**。
- 现状 ORB 配准 + 多段标定已兜住"偶尔被碰"，痛点不成立。**列需求池待议，不排期。**

### T4 · 学习型筐口判据（阶段/进球外观当类别）｜不推荐

- 与我们 v18 判定的优势互斥；CNN 仲裁线已在需求池 §3 标"条件触发，绝不盲上"。**不进入实施。**

### 球点选 / HSV 的去留（跟 shooter 挂钩，本仓不动）

- shooter 重构若不再需要 HSV 色域种子 → 球点选整体退役，标定向导瘦身（T2 后 = 纯确认一步）；
- 在那之前球点选**保留**（shooter 的生产依赖）。**shooter 正由另一会话推进，本方案不碰。**
