# v21 筐锚点定位（hoop anchor）——方案与验收

日期：2026-11-07　状态：开发完成，等验收数据　作者：AI（用户「开工」批准）

## 1. 要解决的问题

用户的诉求：**一个视频只标一次筐**，不要在镜头移动后手工补段。

现状是「人工标定 + ORB 全画面配准」。ORB 给的是**相对**位移（相对参考帧动了多少），
误差随时间累积，且失效时完全静默。四场实测（`诊断/2026-11-07-筐识别/结论_只标一次验证.md`）：

| 场次 | 采样 | 筐检出率 | 只标一次、不补段的偏差（中位 / 最大） |
|---|---|---|---|
| 10-17_1 | 378 | 99.7% | 0.46W / 7.09W |
| 10-23_1 | 374 | 99.7% | 0.05W / 3.39W |
| 10-30_1 | 320 | 100% | 0.68W / 1.04W |
| 10-31_1 | 337 | 100% | 0.35W / 2.90W |
| 合计 | 1409 | 99.86%（误检 0.21%） | — |

判定门是 0.30W（review）/ 0.45W（kill）。**四场里三场只标一次就系统性超门**——
用户的痛点是真的。

## 2. 关键洞察

`hoop` 类本来就在同一个 YOLO 模型里（`dataset.yaml: 0=ball 1=hoop`，筐标注 5067 框，
比球还多），只是推理时被 `classes=[0]` 挡掉了。改成 `classes=[0,1]` 后**零额外推理
成本**，而它给的是**绝对观测**——视差、旋转、缩放、摇镜都不影响。

## 3. 为什么不能拿筐位移直接替换 ORB

摇镜是旋转，画面近处与远处位移不同（视差）。12 个镜头突变点里 4 个是摇镜，各区域
位移差达 152~231px（5.8 个筐宽）。这时筐的位移和球的位移本来就不相等，用筐单点去
纠正全画面球点位，会在球所在区域**引入新误差**。

所以定位是：**hoop 消 ORB 解释不了的慢分量，全局位移仍由 ORB 提供。**

```
x_cal = x_raw − shift_orb(t) − c(t)
c(t)  = 时间中值( Δ_hoop(t) − shift_orb(t) )
Δ_hoop(t) = 筐心(t) − 筐心(标定参考帧)        ← 绝对基准，偏置自动抵消
```

- 绝对基准取**标定参考帧**上的筐心（检测时算一次存进 positions.json，重放不再跑推理）。
- **不能**改用「残差中位数自估零点」：漂移常是单向累积的，中位数会把真实漂移吸收掉
  一半，反而把前半段**正确**的几何拉走——修错比不修更糟。没有参考帧基准时直接放弃。
- 3 窗时间中值：抹掉单点误检，完整保留整机平移造成的真实台阶。
- 20s 采样（按帧号 600 帧）：实测 10s/20s 插值误差 P90 均 ≤0.08W；采样越密收益递减，
  而每点都要一次推理。突变只持续 0.8~1.0s（画面全糊、球根本检不到），20s 采样自然
  跳过，价值在于**突变结束后立刻重新锚定**——等价于手工补一段标定。

## 4. 改动清单

| 文件 | 内容 |
|---|---|
| `bbh/hoop_track.py`（新） | `pick_hoop`（按尺寸最接近选框）/ `HoopSampler`（按帧节流采样）/ `build_correction`（→ c 表）/ `remap_positions` / `remap_shift` |
| `bbh/detector_yolo.py` | `classes=[0,1]`；`_best_ball` 按类别过滤（否则会把筐当球）；采样进 `meta` + `hoop_out`；`hoop_center_of`（参考帧基准） |
| `bbh/detector.py` | 签名对齐加 `hoop_out`（HSV 链不用，只为切换检出器时调用不分叉） |
| `bbh/pipeline.py` | `LOGIC_VERSION 20→21`；`_hoop_apply`（段级校正）；块级 `hoop`/`hoop_ref` 落盘与透传；检查点带 hoop；`_hoop_out_kwargs`（第三方检出器兼容）；三条 warning |
| `tests/test_hoop_track.py`（新） | 16 条：框选择、节流、偏置抵消、台阶保留、尖峰抹除、尺寸门、坐标重映射、开关关闭 |
| `tools/remap_hoop.py`（新） | 存量场次补采样（只跑筐那一路，每场约 45 秒；positions/shift 不动） |

**DETECT_VERSION 不动**：positions 里存的仍是 ORB 校正后的坐标，筐校正只在判定阶段
叠加。所以存量场次的检出缓存照用，补完采样后**重放判定即生效（秒级）**，不需要几十
小时重检。

## 5. 顺带修掉的两个既有缺陷（验收时被踩出来）

这两条都不是 v21 引入的，是拿着 10-17_1（4 段、其中 seg1/seg2 **标定指纹完全相同**）
做对照时暴露的：

**① `_block_covers` 恒真**（`pipeline.py`）。`t1` 非空时原实现把 `end` 赋成 `t1`
本身再拿它比 `t1`，永远成立 —— 于是「指纹相同的另一段」的块会被当成覆盖本段。
10-17_1 的 seg2（18.8~101.6min）就这样拿到了 seg1（0~18.8min）的检出数据去判定，
events 只剩 158 行（正常 398）。修法：必须真读到块的 `t1` 且它罩到段尾。

**② 同指纹多段在缓存索引里互相覆盖**（`_blocks_from_doc`）。原来用
`{指纹: 块}` 字典，seg1/seg2 指纹一样 → 后段覆盖前段 → 前段查不到块就重扫，
而重扫完只写回自己的块、把其余段**整批冲掉**（实测 4 段存档缩成 1 段）。
改成块列表 + `_find_block`（先按「指纹 + t0≤0.5s」精确匹配，找不到再退回
「指纹 + 窗口罩住本段」兼容旧扁平全片存档）。

**③ 增量落盘冲掉未处理的段**。`persist_blocks` 只收集本次循环跑过的段，
多段跑中途取消/中断时写盘会把还没轮到的段丢掉。改成「本段块 + 尚未被本次
替换的旧块」。这是 10-17_1 丢段的直接原因（第 2 段扫描中被 SIGTERM 杀掉）。

## 6. 验收口径

| 项 | 判据 |
|---|---|
| 回归（硬护栏） | `BBH_HOOP=0` + v20 逻辑 → events 与升级前**逐条相同** |
| 等价性 | v21 + 无 hoop 采样 → events 与 v20 逐条相同（坐标链路未被动过） |
| 增益 | 补采样后重放，变化只出现在「只标一次偏差超门」的时段；不得新增整段假绿 |
| 单测 | `pytest tests/` 全绿（含 16 条新测） |
| 视觉抽查 | 变化行前后抽帧看筐位，确认是「修对了」而非「挪错了」 |

## 7. 已知限制

1. **摇镜 1~2 秒不可信**：那段球点本身就废，任何单一位移模型都救不了。策略是忽略 + 事后归位。
2. **变焦只告警不跟随**：判定阈值全按筐宽算，尺寸跟错比位置跟错更糟。尺寸离群 >15%
   的样本占比超阈值 → 提示「建议补一段标定」。
3. **参考帧与检测画面分辨率不同 → 放弃校正**（避免在标定框上做二次缩放）。
4. **跨段冷却** `_merge_segment_events` 未改（本次不涉及）。
