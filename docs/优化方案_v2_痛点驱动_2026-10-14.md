# 优化方案 v2 · 痛点驱动（归人 / 复核降本）

- 日期：2026-10-14
- 关系：`优化方案_竞品对比与可优化项_2026-10-14.md`（v1）经审查后**降级为「技术机会清单」**（不排期）；
  本文件（v2）是审查后按**真实痛点**收敛出的可执行方案。
- 评审方式：`grill-me`（逐分支追问）。审查结论：v1 是"由调研+代码推出"的机会清单，
  **不是"由痛点推出"的待办**；本项目当前**唯一真实痛点=归人/复核太耗人工**。

---

## 0 结论先行

1. **自动化上限已封死**：外观 reID 自动归人（层2）已**证伪**（OSNet 同人/异人余弦 0.701 vs 0.700，
   对拍 11~14%）；持球链（层1）按球开窗，实测 **107 tracklet ≈ 109 球**，**无归并**。
   → "全自动识别+归类"**不是可选项**，是已知不可达。
2. **能做的只剩三件事**：把溯源**做准**（GIF 里框住的真是出手人）、把呈现**做清**（GIF 形式）、
   把操作**做快**（键盘化/焦点人/批量）。外加**复核裁决降本**。
3. **第一步是诊断而非开发**：须先钉死"出手人识别不准"的具体形态，才能决定 L1 做不做。

---

## 1 痛点与目标（重新定义）

| 项 | 内容 |
|---|---|
| 真实痛点 | 归人环节的**认人判断** + **复核裁决**耗人工；且**出手人溯源不准**、GIF 形式可优化 |
| 原目标（用户理想） | 自动识别出手人 + 自动归类 |
| **诚实目标（v2）** | ❌ 不做全自动归人；✅ 做「看得清 + 点得准 + 点得快」；把溯源做准；复核批量/键盘化 |
| 量化口径 | 单场「归人+复核」的**总点击次数 / 总耗时**（需先测基线） |

## 2 可执行项（按预期收益排序）

### L1 · 溯源精度：让 GIF 里框住的真的是出手人  【先诊断，SPIKE 门控】
- **先诊断**（未定，待确认）：不准属哪种——
  ① 拍错人（定位到别人/背景）｜② 认不出（糊/远/短）｜③ 十字偏（标记非出手点）｜④ 覆盖不够（⚪🟡 多）
- 若属 **①③**（上游溯源精度）→ **A2 出手回扫从 HSV 换/混合 YOLO**（这是 v1 里 O1 的"对症版"；
  HSV 现走全帧 + S 地板 SCAN_S_FLOOR=88 + 抛物线外推 + 局部复扫，对"球的身份"无判别力）。
  - **Spike 门控**：先 08-28/09-04 各 20 球对拍「GIF 框内是否=真出手人」，达标再全量。
  - 风险：远景小球 YOLO 召回未验；不达标则回退 HSV + 混合。
- 若属 **②** → 走 L2（是呈现问题，不是溯源问题）。
- 若属 **④** → 处理 ⚪/🟡 兜底路径（`release_spot_bad` / 全场图兜底）。
- **落点**：`bbh/shooter.py`（`scan_release_window` / `_rescan_release`）、`bbh/detector_switch.py`
- **验收**：`tools/check_shooters.py` 门（缩略图有效率 ≥80% 且无系统性偏差）前后对照

### L2 · 呈现优化：GIF 形式（你明确指出可优化）  【纯前端，零风险】
- 方向（择优选，可叠加）：
  - a) 行内**短视频**替代/伴随 GIF —— GIF 无音、低帧、调色板失真；视频更利于"认人"（已有 `bbh/web/media.py` 与 clip 生成能力）
  - b) **加长窗**（出手前 0.7s → 更长，让动作可辨）
  - c) **加宽取景**（多带身材/衣着/周边，利于认人）
  - d) 墙视图沿用（已 v4 放大 640 + 6 列）
- **落点**：`bbh/vrender.py`（GIF 渲染）/ `bbh/static`（展示）/ `bbh/web/media.py`
- **验收**：同批球新旧呈现对照，测**认人耗时**下降

### L3 · 交互降本：把"每球一次操作"变快  【纯前端，零风险】
- **数字键选人**（1..N，ShotCut 做法）
- **焦点人模式**（先选人 → 逐球 y/n 快速过，hoopclips 做法）——最适合"剪某人个人集锦"
- **分配即自动跳下一个未分配** + 完成度闸门（reborncd 做法）
- **列表键盘导航**（↑↓ 选行、空格勾选）
- **落点**：`bbh/static`（出手人 tab）+ `bbh/web` API
- **验收**：单场点击次数 / 耗时前后对照

### L4 · 复核裁决降本
- **键盘 y/n 裁决**（现为鼠标点「✅/❌」）
- **批量裁决**（选区一次裁定）
- **档位/原因过滤**（先清 🟢 或先清 ⚪）
- （可选，需你拍板）**重新审视 HIGH_CONF**：v18 从 0.70 降到 0.65 后，八场假绿 288→**469** ——
  **复核量本身变大了**，这可能正是"复核越来越耗"的一个新来源；回到 0.70 可减复核，代价是掉一点命中。

## 3 顺序与依赖

```
诊断"不准"形态 ──┬─(①③)→ L1 Spike（换/混 YOLO）→ 全量
                └─(②)──→ 并入 L2
L2 呈现 ┐
L3 交互 ├─ 三者独立、纯前端、可并行（零风险，先出可见收益）
L4 复核 ┘
```

- **推荐起步**：L2 + L3 + L4 并行（纯前端、零风险、直接省力），同时做 L1 的形态诊断。
- L1 的 Spike 只在形态确认为 ①③ 时触发。
