# 出手人识别（谁投的）设计

日期：2026-08-23
状态：设计已与用户逐节确认（五节全过）

## 背景与目标

进球判定（v10）与按人集锦（手动打标签）已可用。用户需求：**自动判断每个
进球是谁投的**，减少逐条看视频手动打标的成本。

验证数据已就绪：`truth/*.json` 的 `shooters` 字段——08-22 共 125 条
出手人标注（16 人）、08-21 共 100 条（12 人），两场人群高度重叠。

## 方案选择（已拍板：A 分两步落）

| 方案 | 内容 | 结论 |
|---|---|---|
| **A（选定）** | 出手溯源 + 外观聚类 + 每组一次命名，分两阶段落地 | 零模型依赖起步、风险分阶段释放、225 条标注可全程验收 |
| B | 只做溯源+缩略图（A 的第一阶段） | 不省手标次数，作为 A 的 Phase 1 吸收 |
| C | YOLO+ReID 端到端 | 与 2026-08-22"等更多标注数据"决策相悖；225 条不够训 ReID |

**YOLO 调研结论**（2026-08-23）：行业解"谁投的"靠球衣号码或人脸识别，
咱们的野球局两者皆无（无号码、机位远脸仅 ~12×14px）；现成篮球 YOLO
模型/数据集均为转播视角、记分牌导向，与固定半场机位不匹配；咱机位球仅
5-10px，YOLO sports ball 检测不到，球检测继续用自家 HSV。YOLO 的定位
是 **Phase 2 可选增强零件**（person 框精确定位人体提特征），不进第一期。

## 总体架构

新模块 `bbh/shooter.py`，独立于现有检测管线，不动 `detector.py` /
`pipeline.py` 的任何缓存身份——出手人识别完全失败也影响不到现有进球检测。

```
现有管线（不动）                     新增 shooter 模块
────────────────                     ──────────────────────
检测(ROI=筐口周边)                   出手溯源（按需回扫全帧）
  → positions.json                    → shooters.json（独立缓存）
判定 → events.json                   射手裁剪 → 缩略图
勾选/标签 → selection.json           [Phase 2] 外观聚类 → 分组建议
```

**缓存**：`work/<视频>/shooters.json`，身份键 = 视频 + 标定指纹 +
`SHOOTER_VERSION`（独立版本号，放 shooter.py）。**不碰 `DETECT_VERSION`**——
溯源调参只 bump 自己的版本，按需重扫进球前几秒（约 10 分钟），绝不触发
全片重检，也不动测试集的 positions.json 缓存。缩略图目录
`work/<视频>/shooters/`（每球 2 张 jpg，162 球约几十 MB）。

**Phase gate**：Phase 1 做完必须过验收（见下）才开工 Phase 2。实现计划
拆成两个阶段，不是一个计划硬塞。

## Phase 1：出手溯源 + 射手缩略图

### 溯源算法

1. **回扫窗口**：进球时刻 t 往前 6 秒（覆盖三分高弧线 ~2s + 抢板补篮/
   争抢再出手余量），对这段做**全帧** HSV 球检测（复用标定 HSV，区域从
   筐口 ROI 扩为全画面——现有检出流只覆盖筐口 6 筐宽×13 筐高，出手点
   在三分线从未被检测）
2. **降采样**：隔 2 帧取 1 帧（15fps），每球约 90 帧、~3 秒
3. **轨迹回追**：从进球穿越点沿检出点时间倒序回追，相邻采样点距离在
   球速上限内连成链，允许 0.3s 短缺口桥接（遮挡/瞬断不断链）
4. **出手点判据**：飞行段特征=单调接近筐、速度连续；**持球段**速度低、
   方向乱。回追到"速度从低跃变到高"的点 = 球离手瞬间 → 出手点
   (x, y) + 出手时刻。追到 6s 窗口边界仍无跃变 → 低置信（出手更早或
   轨迹断了），照样出结果但标出来
5. **置信度三档**（沿用列表三档色点视觉语言）：
   - 🟢 轨迹完整 + 找到跃变点——缩略图基本可信，看图直接打标
   - 🟡 轨迹短/缺口桥接/追到窗口边界——出手点位置可能偏，打标前多瞟
     一眼预览
   - ⚪ 未溯源（全程被挡/出手点在画面外）——无缩略图，手动看视频打标，
     同现状
   - 三档判定规则（轨迹点数/覆盖时长/跃变点）的具体阈值在 225 条标注
     上标定——先看分布再定阈值，不拍脑袋

**隐含假设**（Phase 1 实测验证）：出手前球在人手里时 HSV 也能检出球
（球是大块橙色）——"持球段→飞行段"速度跃变可检测。

### 射手裁剪

- 像素换算用筐宽（筐直径 45cm）：人高 ≈ 4 倍筐宽像素，透视误差放大
  1.5 倍余量
- 裁剪框：出手点为上界，向下裁全身（体型/鞋 Phase 2 用），左右放宽
- **两帧**：出手时刻 + 出手前 0.3s（持球姿势帧，通常最好认）
- 轨迹没追到/出手点在画面外 → 该球"未溯源"，不硬给图

### UI 与交互

- 左栏结果区小按钮「🧍 识别出手人」：批量跑，生成器化进度
  `⏳ 识别出手人（k/N）`（复用生成集锦进度模式）；已有缓存秒载不重跑
- 行面板（预览下方）加"出手人"区：两帧缩略图（出手点十字标记）+
  置信度三档小标 + 高置信号码时标"疑似 #N"
- **Phase 1 不自动写标签**——看缩略图手动打标（打标即自动勾选照常生效）。
  价值=不用逐条点视频回看出手，一眼看图打标

### Phase 1 验收（gate）

- 自动指标：轨迹回追成功率（多少球追到出手点）、出手→进球间隔分布
  （合理区间 0.3~4s 占比，离群=追错轨迹）
- 人工指标：`tools/check_shooters.py` 对两场 225 条标注生成对照表
  （每行=缩略图+用户当时标的出手人名），用户肉眼扫一遍
- **通过标准：缩略图有效率（对照表里缩略图确为出手人的比例）≥80% 且
  无系统性偏差**（如总慢半拍裁到防守人）；不达标先修溯源，不带病进
  Phase 2

## Phase 2：外观聚类 + 每组一次命名

### 特征体系（定稿：零模型依赖起步）

固定机位先天优势——标定参考帧即干净背景，**背景差分**直接分割人形
轮廓，不需任何模型：

| 特征 | 内容 | 角色 |
|---|---|---|
| **三段颜色指纹（主）** | 人形掩码按高度切三段各自 HSV 直方图：上衣 0~50%（权重最高）/ 裤子 50~80%（短裤 vs 长裤的覆盖率本身是区分特征）/ 鞋 88~100%（十几像素、低权重第三票） | 主力 |
| **头部特征（仲裁票）** | 掩码顶部 ~15%：发色直方图（最上段，含光头判定）+ 面部肤色（剔头发后平均 HSV）。黑发/白发/光头/肤色深浅在咱分辨率下可辨；眼镜胡须脸型不存在 | 低权重、**只拆不合**：三段颜色都相似时头发肤色明显不同 → 拆开标待确认 |
| **高置信号码（强锚点）** | 上衣段轻量数字识别带置信度。高置信：号码同且颜色似→强合并、双方高置信号码异→拆分；低置信/读不清→静默忽略（8 认成 3 就乱套）。UI 顺带展示"疑似 #N"辅助命名 | 加分项不是支柱（预期少数人穿号码服） |

细节处理：
- **皮肤剔除**：短裤场景裤段混入腿部皮肤——HSV 皮肤区间像素从掩码
  剔掉再算直方图，否则满场短裤"同色裤子"
- **缺失段**：某段被挡/出画面 → 置缺失不参与比对，整体置信度降档——
  缺失就少一票，不拿空段瞎算
- **分段比例**：人体平均比例+容差带（投篮手上举会略变）；225 条实测
  不够再按掩码最宽处定位肩/臀精化
- 时空硬约束（**只拆不合**）：进球时刻几乎相同的两个射手必是不同人；
  同组内时间冲突成员直接拆

### 聚类

- 两两相似度超阈值连边 → **连通分量**=组，组数不预设（一场 12~16 人
  自然聚出 12~16 组）
- 合并门槛从严：颜色相似**且**体型相似双条件 AND（宁拆勿错并：拆开
  =同一人多打一次名字；错并=一串球全标错人）
- **链式错并防御**：A 像 B、B 像 C、A 不像 C 时组内两两复检，最不像
  的拆出去单列
- 相似度边缘带标 🟡"疑似撞衫"，要求逐张看组内图再命名

### 换衣服场景（已论证：天然落在安全方向）

换衣导致**拆**（同人前后两个指纹→两组）——恰是宁拆勿错则的安全方向，
代价=同人命名两次。唯一危险角落（换上与他人一模一样的衣服）已有两道
防线：时空硬约束（同时在场必拆）+ 头部仲裁票（衣服换了光头还在）。

### UI 流程

识别出手人跑完后出"分组命名"面板：
- N 个组按人数排序：代表图 + **全部组员缩略图**（混入者一眼可见）
- 每组一个下拉（复用现有标签库/新增标签弹窗）选名字 → 整组继承写入
  现有标签体系（`tag_assignments.json`，打标即自动勾选照常生效）→
  照常生成按人集锦
- **手动并组**：选中两组→"合并"——拆是算法保守，并是用户一句话
  （宁拆勿错并的配套，换衣服/孤点/边缘相似度产生的多余组靠它兜）

### Phase 2 验收（gate）

225 条标注重放：**分组纯度 ≥95%、错并 = 0 或全部落"待确认"档**。

## 阈值标定纪律（铁律，贯穿两阶段）

任何阈值（置信度三档边界、聚类相似度阈值、号码置信门槛）**必须先在
225 条标注真值上画分布验证分离度再定**——同一人特征距离 vs 不同人特征
距离的分布重叠即该特征不可用（如头部特征方差大于人际差异则弃用该票）。
与进球判定调优同一纪律，不拍脑袋。

## 错误处理与边界

| 情况 | 处理 |
|---|---|
| 回扫窗口跨视频开头（进球在开片 6s 内） | 窗口截断到 0，照常扫 |
| 相邻进球间隔 <6s（窗口重叠） | 各球独立扫、按球键缓存，互不干扰 |
| 裁剪框出画面边界 | clamp 回画面内 |
| 中途中断/关页面 | 逐球写盘——已完成的球不白扫，重跑续上（同检测检查点思路） |
| 重标定 / `SHOOTER_VERSION` 变更 | shooters.json 身份不符整档作废重扫（复用现有缓存身份模式） |
| 某人只进 1 球（孤点） | 自成一组照常命名；多余组靠手动并组兜 |
| 重跑检测后新增进球 | 新球增量溯源+归组，已有分组不重算 |

## 成本预算

每球回扫 ~3s × 162 球 ≈ **10 分钟一次性**，纯 CPU 后台，跑完进缓存
秒载。聚类本身秒级（162 个特征向量）。
