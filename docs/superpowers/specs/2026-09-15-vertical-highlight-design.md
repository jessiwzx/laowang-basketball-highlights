# 竖屏运镜集锦（跟人→移筐 + 慢动作 + 白闪）设计

日期：2026-09-15。上游：两条抖音参考片的定量拆解（`视频参考/_analysis/`
下的 motion_analysis / camera_trace / extract_strip 临时工具产出）。

## 背景与问题

现集锦链路（`editor.py` 的 `plan_clips → cut_clip → concat_clips`）产出
1280×720 横屏、直切硬拼、无运镜无慢动作无转场——抖音播放效果差。本设计
把成品替换为参考片同款手法：竖屏全屏画幅 + 关键帧虚拟运镜（跟出手人 →
快进球时移到篮筐）+ 进球瞬间慢动作 + 白闪转场。

## 参考片实测（证据摘要）

| 维度 | 实测 | 手段推断 |
|---|---|---|
| 画幅 | 592×1280（1:2.16 ≈ 19.5:9）30fps HEVC | 全屏沉浸式，抖音端再放大 |
| 单球节奏 | 3-4s/段 | 出手前 hold → 平移 → 慢动作 → 原速 |
| 运镜 | 静止 hold 1-1.5s → 缓动平移（峰值 35-45% 画宽/s，累计可达 54% 画宽）→ 进球时锁筐（速度归零） | 关键帧 + 缓动插值；zoom 全程 ±2.6% ≈ 恒定 |
| 慢动作 | 0.2x、输出段 1.3-1.7s、镜头锁定、帧间连续无复制 | 高帧率源或 AI/运动补偿插帧 |
| 转场 | 片间白闪 1-2 帧（常双闪）；片内直切；结尾定帧淡出 | 白帧插入，非 xfade |
| 包装 | 榜单序号卡（定帧+大号数字） | **用户拍板不做** |

源约束（关键）：我们的源全部 1920×1080@24fps 固定机位。0.3x 慢动作 =
3.3x 补帧，必须插帧；固定机位 + 现成球场标定 ⇒ 运镜不需要逐帧跟踪。

## 方案选型

- **A（采纳）**：标定数据算 3 个关键帧 → 缓动插值出逐帧裁剪中心 →
  `cv2.warpAffine` 浮点裁剪 557×1080 → 放大 660×1280 → rawvideo 管道喂
  ffmpeg 纯编码。零新依赖；GitHub 同类项目（auto-vertical-reframe /
  glide-ffmpeg / Super-View-Crop）全走此路线。
- **B（否）**：CSRT/检测器逐帧跟人。漂移/遮挡失败模式多、CPU 重、调参
  负担大；参考片观感是「定→移→定」而非连续跟拍。留 v2 升级位。
- **C（否）**：ffmpeg zoompan/xfade 纯滤镜链。zoompan 整数取整导致运镜
  周期抖动（ffmpeg Trac #4298 无解），且做不了跟人关键帧，同类项目无
  一采用。

## ① 导出规格

| 项 | 值 |
|---|---|
| 分辨率 | 660×1280 @30fps（1:1.94；2026-09-25 用户裁定 B 方案：592×1280/1:2.16 → 660×1280，视场 +11% 看到更多内容） |
| 内容缩放 | `content_scale=0.80`（2026-09-25 用户裁定档1，k=1.0/0.80/0.65/0.50 四档样片里挑的）：画幅比例不变，内容缩到 660×1024 纵向居中，上下各 128px 留白填充（**2026-10-18 用户裁定 A 案：`fill_mode="black"` 纯黑**，原同帧模糊口径保留为 `fill_mode="blur"` 可逐位切回；改因：模糊底在广角场馆糊出脏灰，观感像渲染出错）。可见源窗随之由 371px 变宽到 464px（源宽 29%→36%），主体在手机上按 0.8 缩小。全程仍是单一均匀缩放（零畸变）。留白高度只由 k 决定，与源分辨率无关（720p/1080p 源景别一致，仅清晰度不同）。代价：相机横向余量 ±455px→±408px（k 再往下调运镜余地更小，k≈0.26 时全源可见=运镜锁死） |
| 裁剪 | 源 1920×1080 裁 500×1080 → ×1.185 放大（窄裁=主体大；不自上变换到 1080×1920，放大交给抖音端）；content_scale<1 时裁窗按 1/k 变宽、输出侧留白 |
| 编码 | H.264 CRF 19 + AAC 128k |
| 音频 | 常速段保留现场原声；整条 loudnorm −14 LUFS；慢动作段静音+0.1s 线性淡入出。BGM 不进 v1（留槽位） |
| 命名 | highlight.mp4 / highlight-<标签>.mp4（沿用现有约定） |

## ② 每球时间线 + 运镜引擎

单球时间线（t = 进球时刻，窗口 `[t−前, t+后]` 由现有前后秒规则划定）：

```
t−5.0        t−1.10        t−0.35    t       t+0.25      t+2.0
   │◄─ hold ─►│◄── pan ──►│◄─slowmo─►│◄─ aftermath ─►│
   锁出手人     出手人→篮筐   锁筐 0.3x    锁篮筐
```

关键帧来源（全部现有数据，零新增检测）：

| 锚点 | 来源（写实现计划核对仓库后修正：全库无 homography，以下坐标本就是视频像素） |
|---|---|
| 出手人像素位置 K0 | shooters.json `traces[time_key(t)]["release_xy"]`——已是视频像素坐标；`spot=="bad"` 或缺失 → 无 hold，整段锁筐 |
| 篮筐像素位置 K1 | 该球所属标定段 hoop_rect 经 `detector._scaled_rect` 缩放到视频分辨率后的筐口中心 x（多段标定按进球时刻选段，与检测同口径） |
| 出手时刻 | `traces[key]["release_t"]`；缺失缺省 `t − 1.1s`（参数） |

运镜**仅横向**：裁剪窗吃满源高（500×1080），cy 恒 = 源高/2，只有 cx
变——与参考片实测一致（dy≈0、zoom≈1.0）。content_scale<1 时可视窗宽变
成 `cw/k`，钳制与速度预算都按这个窗算（否则窗心越界会露出源画面外），
输出侧峰值速度恒为 0.45×out_w px/s、与 k 无关。

平移段公式：`pan结束 = t − 0.35s`；`pan时长 = clamp(max(出手→进球间隔 −
0.35, π/2×位移/(0.45×可视窗宽)), 0.5, 1.8)s`（飞行短则提前起跑防甩鞭；
位移大则拉长保峰值；1.8s 封顶宁快勿拖）；正弦 ease-in-out，峰值速度目标
≤45% 可视窗宽/s。**zoom 恒定**（v1 无变焦关键帧，留参数位）。

路径生成：逐帧中心点先离线算成数组 → 5 帧滑动平均（消关键帧衔接折角，
GitHub Super-View-Crop 同款）→ 边界钳制（裁剪窗不出画面；出手人贴边时
中心内收）→ 一遍渲染。路径数组是纯函数输出，可独立单测。

渲染：`cv2.warpAffine` 逐帧浮点裁剪（subpixel 无整点抖动——弃 zoompan
的根本原因）→ 内容按 k 缩到 660×(k·1280) 居中，k<1 时上下用同帧 1/8
缩放的模糊底填充（黑边在手机上像拍坏了）→ 画幅 660×1280。k=1.0 与旧
口径逐位相同（单测钉住）。

## ③ 慢动作

- 默认窗口 `[t−0.35, t+0.25]`（0.6s 源 → 2.0s 成品）。参数 `slowmo_speed=0.3
  / pre=0.35 / post=0.25`；`slowmo_mode=rim`（默认，参考片同款：球压筐→
  穿网→进球后一拍）/ `flight`（出手→进筐全飞行，每球 +3-4s，完播率风险
  自担，仅实测后确认需要才用）。
- 与用户最初描述的差异已在对话中对齐：参考片慢动作在进球瞬间而非出手
  时刻，出手时刻是前段静止 hold；默认跟参考片。
- 窗口被极小前后秒截短时自动收缩；不足 0.2s 该球跳过慢动作（降级原速）。
- 链路：**裁剪先行，插帧在小分辨率上做**——Python warpAffine 输出
  660×1280@24 后一次性喂 ffmpeg，filter_complex 三分时间线：常速段
  `fps=30` 补帧；慢动作段 `minterpolate=fps=100`（me_mode=bidir、
  mc_mode=aobmc、vsbmc=1）→ `setpts` 拉伸 → 采 30fps；三段 concat。插帧
  在 660×1280 而非 1080p 源上，耗时降一个量级（0.6s 窗 ≈15 源帧→100
  插值帧，秒级）。
- 伪影退路：快球/人交叉轻微 morph 时先降该段 0.5x（插值倍率减半），仍
  不行调 `me_mode=bilat`。

## ④ 转场与组装

- 片间白闪：每两球间插 **2 帧全白**（30fps 下 66ms），不用 xfade；可配
  `hard_cut`。片内各段直切。
- 片头无标题卡；片尾末球 0.5s 定帧→淡出黑（可关）。
- 组装：每球独立渲染成**参数完全一致**的段（660×1280@30fps H.264）+
  白闪微段（2 帧白场+静音，同规格）→ concat demuxer 流拷贝硬拼（零重编码）。

## 错误处理与兜底

| 场景 | 行为 |
|---|---|
| 出手点 bad / 无 shooter 数据 | 跳过 hold，整段锁篮筐（退化但不断产） |
| 出手时刻缺失 | 缺省 `t − 1.1s` |
| 篮筐反投影出画面（标定异常） | 钳制到画面内；仍异常则整球退化为画面中点 |
| 慢动作窗 <0.2s | 该球跳过慢动作 |
| 片段贴视频首尾 | 沿用现有 `max(0.001, start)` 防护 |
| 单球渲染失败 | 记日志跳过该球，其余照常出片（集锦不因一球全废） |

## 测试与验收

1. 单测（`plan_camera` 纯函数）：缓动曲线单调、峰值速度 ≤ 钳制值、裁剪
   窗不出画面、bad 出手点走兜底、滑平均后无折角/NaN。
2. 冒烟：真源 09-11_3 渲 3 球——验规格（660×1280@30）、逐帧裁剪中心位移
   曲线平滑（回归「运镜抖动」头号敌人）、慢动作段帧间连续（无复制帧）。
3. 实机验收：成品发手机与参考片对照。
4. 性能：一场 15 球预计 3-5 分钟。
