## 特征提取（每球 → 外观指纹）

**源**：回 `det-source`/原视频 `release_t` 帧附近提取，**不用 Phase 1
缩略图 jpg**（缩略图为验收裁的、深度自适应放大过、混入背景，特征口径
不统一）。

**人形分割（per-球 局部中值背景）**：

1. 窗口 `[release_t − 2.5s, release_t + 2.5s]` 均匀采样 ≈15 帧（步进
   按帧率取整），逐像素中值 → 背景帧（球员跑位/起跳是移动的，中值把
   他们洗掉）
2. 目标帧（`release_t`；掩码质量差时退回 `release_t − 0.3s` 持球帧，
   两帧都不行 → 该球特征缺失）与背景帧 absdiff → 阈值 → 形态学开闭 →
   连通域
3. **目标人选取**：包含出手点 `(rx, ry)` 或其正下方小偏移的连通域优先
   （出手点=球在人手里，必在人形上沿附近）；无包含则取中心与出手点距离
   < 1 人高的最大连通域；都不满足 → 特征缺失（宁缺勿错）
4. 已知残余风险：出手人在整个窗口基本静止会被中值洗掉 → 找不到目标人
   → 该球特征缺失。可接受，不硬补

**指纹构成**（按人形掩码自身 bbox 竖切，不按裁剪框）：

| 特征 | 内容 | 角色 |
|---|---|---|
| 三段颜色 | 上衣 0~50% / 裤 50~80% / 鞋 88~100%（80~88% 为膝部缓冲带不取）各段 HSV 直方图，上衣权重最高、鞋十几像素低权重 | **排序提示**（feat_similar 降序排前 K，恒 low） |
| 体型 | 掩码高/筐宽（同场同机位可比）+ 高宽比；防守人贴身粘连致掩码过宽时置缺失 | 被动展示，不参与判定 |
| 头部 | 掩码顶部 ~15%：发色直方图 + 剔发后肤色均值 HSV | 被动展示，不参与判定 |
| `jersey_no` | 预留字段，恒 None（v1 不做 OCR，见下） | — |

**细节**：
- **皮肤剔除**：皮肤区间像素从掩码剔掉再算直方图（短裤场景裤段混入
  腿部皮肤，否则满场"同色裤子"）。区间初始按 OpenCV 常用肤色带
  （H 3~17 且 S/V 收窄），**必须先在真值样本上校准**——球色 H 1~12
  与肤色同带，纯靠 H 会误剔橙色上衣；用 S/V 饱和度差异区分（皮肤低
  饱和、纯色衣高饱和），分离度不够就收窄皮肤区间
- **缺失段**：某段被挡/出画面/像素数低于下限 → 置缺失不参与比对，
  相似度按剩余段重归一
- **两帧策略**：主用 `release_t` 帧；人形掩码面积过小/粘连异常时退回
  出手前 0.3s 持球帧（通常姿势最完整）

## 手动归人（一等公民）

- 面板：球列表（带缩略图+时间）→ 多选 → 下拉（复用标签库）/新建人名
  → 归人；同人球自动成组
- 归人写入 `manual_groups.json`：身份键=视频名+球 key，与 features/
  groups 版本**完全解耦**——特征重算/重聚类不触发作废，手动标签是
  事实不是缓存
- 归人即写 `tag_assignments.json`（打标即自动勾选照常生效）→ 按人集锦
  照常
- 已归组球可改判（移到别人/撤销）；改判同步更新 tag_assignments；
  移出只动 manual_groups 不碰已打的标签
- MIN_GOAL_GAP_S 校验：勾选集合内任两球间隔 <2.5s → 警示不阻断
  （用户永远赢）
- 初版"待确认区/手动并组/疑似撞衫标注"取消——没有算法组就没有挂不上
  的球；组=人，归错重新归

## 建议钩子（可插拔）

```python
# bbh/suggest.py（新模块）
@dataclass
class Suggestion:
    balls: list[str]          # 建议 same-person 的球 key
    person: str | None        # 若该人已在 manual_groups 中则带名字
    signal: str               # "color_rank"
    confidence: str           # 恒 "low"（v1）
    evidence: dict            # 证据：相似度值/分段明细

def suggest_groups(features, manual_groups) -> list[Suggestion]: ...
```

护栏（全部硬编码不可配置）：
1. 建议永不自动生效——UI 上是"可采纳的候选"，采纳=写入 manual_groups，
   忽略=记入 dismissed（同建议不重复弹）。（v1 现实：颜色提示是内联静态行，
   无采纳/忽略按钮，dismissed 机制留待后续"建议卡"形态再挂）
2. 置信标注默认可见；颜色信号恒 low
3. 手动永远赢：已手动归人的球不再出现在建议里；建议与手动冲突时手动优先
4. 任何新信号源上线前必须过评估工装（两场真值重放，建议簇 vs 真值，
   纯度+覆盖率达标才接入）

### v1 信号源（定案 2026-08-29：OCR 自动建议不进 v1）

- **颜色排序提示（进 v1）**：选中一球时，其余球按 feat_similar 降序排
  前 K 个提示"颜色相近"。两场精度≈抛硬币（AUC 0.53-0.56），定位=排序
  提示，不指望省时间，永不单独定身份
- **OCR 自动建议（不进 v1）**，四条证据（progress ⑦⑧⑩⑪⑬）：
  1. 本地 RapidOCR（唯一可本地生产腿）主体归因覆盖率 ~10-15%——检测器
     读不到 10px 主体数字，读到的多为旁观者/场馆广告（'26' 出现在 4 个
     不同人的裁剪里=篮下常驻人员污染）；位置过滤+同人投票后 08-21 零人
     收敛、08-22 仅 2/16 人
  2. VLM 读数采样不稳定（同图同提示词两次调用一次"23 置信度中+详细笔画
     分析"一次"无法辨认"），且跨帧一致性排除不了"同一模糊斑的系统性
     误读"——精度会话内不可校准，唯一校准源=认识球员的用户本人
  3. 第三模态复检：RapidOCR 直读原生裁剪 0/3 可读主体号码
  4. **伪影证据**："短裤左腿两道竖笔=11"印记在 ≥7 个不同人身上反复出现
     ——跨帧投票的核心假设（一致⇒正确）被直接证伪；"11"在 08-22 复现
     （阿煌/小左/yy 各 1 帧）。阳性对照复盘（⑬）：唯一双模态一致数字
     （084 的 '9'）经亲自看图确认在**旁观者**（"JasonLiu" 定制球衣）身上
     ——中心区位置过滤≠主体归属、OCR 高置信读数同样可能是旁观者
  - 风险模型：'22×3帧'式建议自带伪权威外观（3 帧一致！），未验证精度
    的号码建议比没有建议更糟——制造虚假置信，违背"粗标+核对"的产品
    前提（粗标指程序真能粗略做对的事）
- **号码证据被动展示（进 v1，零新机制）**：手动归人面板的放大裁剪本就
  是核心 UX；号码阅读辅助=同一张裁剪，用户自己读数。不叠加 OCR 框
  （检出多为旁观者，框出来反而误导）
- **后续路线（已终审关闭，2026-08-31 用户语料校准）**：用户核对 11 条
  盲读主张——**命中 1/11**（仅 08-22 阿林=9），且 **8/11 的人球衣根本
  没有号码**（08-21 仅小左=13 有号，主张 23 系一位之差；08-22 老杨=73，
  主张 9 疑只读到一位；yy 无号码，主张 23 纯幻觉）——盲读在无号码素材
  上稳定产生号码幻觉，与真号码不可区分；号码覆盖率本身也低（每场
  1~2 人），即使读对天花板也只有个位数百分比的人。"命中率可观"前提
  不成立，**OCR/盲读线永久关闭**，v1 形态（手动归人+颜色排序恒 low）
  即终局

## UI 流程

「🧍 识别出手人」按钮链路扩展：溯源（Phase 1）完成 → 自动接特征提取
（逐球进度，同按钮禁用模式）→ 出「归人」面板。已有 features.json 的
球跳过（增量续跑）。面板内容：

- 球列表（缩略图+时间+档位），复用 events_table 的"选中"列多选
- 选中后：颜色相近提示（feat_similar 降序前 K，恒标 low，可采纳/忽略）
  + MIN_GOAL_GAP 护栏警示（<2.5s 间隔物理不可能同人）
- 归人下拉（复用现有标签库 tags.json/新增弹窗）→ 写 manual_groups +
  双写 tag_assignments → 照常生成按人集锦
- 已归人球显示所属人，可改判/撤销
- 号码证据=放大裁剪被动展示，用户自己读

## 验收（新口径）

- **手动归人可达性**：两场任一人可在面板上完成"多选→归人→改判→撤销"
  全流程，tag_assignments/按人集锦正确联动
- **建议不干扰**：建议恒 low、永不自动生效、不含已手动归人的球（v1 内联
  提示无 dismissed 机制——该项随建议卡形态再验收）
- **护栏有效**：两场真值重放 0 违例（真值同人最短间隔 3.3s > 2.5s）；
  构造 <2.5s 间隔归人 → 警示出现且不阻断
- **真值重放**：eval_suggestions 报告颜色建议的纯度/覆盖率（预期低，
  报告作基线不设 gate）
- 现有测试零回归

## 错误处理与边界

- 人形掩码取不到 / 多人粘连不可分 → 特征缺失 → 该球无颜色提示（仍可
  手动归人），不硬给
- 特征提取单球异常不 raise：记 `err` 继续下一球（同 trace_video 惯例，
  生成器中途 raise 会让 UI 按钮永久卡灰）
- manual_groups.json 损坏 → 备份后重建空文件，不让 UI 崩（同
  selection/tags 容错惯例）
- 08-21 场用 positions.json 存档标定指纹构造 Calibration（hoop 840,
  423,54,22 / ref `5e4ee089`），**不可用当前全局 calibration.json**
  （08-22 指纹，直接用会身份不符）
