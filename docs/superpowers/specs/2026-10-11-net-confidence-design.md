# 篮网证据进置信度、档位阈值化（Design）

**日期**：2026-10-11　**状态**：已实现（LOGIC_VERSION 18，2026-10-11）
**上游裁定（用户原话，2026-10-11）**：「目前的篮网判断逻辑，应该体现在置信度上，最终根据置信度得到档位高、待、低，而不是直接根据篮网状态升降级。」「保留硬门，所有球都需要走篮网的判断，不然置信度分值就会不准呀。」
**前置**：问题①（B2 注入行置信度硬编码 0.30）当天已修（LOGIC_VERSION 16→17），本设计落地时为 **v18**。

## 1. 背景与现状（代码锚点）

现行判定链里「置信度」与「篮网」是两条互不相通的轨：

- **置信度**（`goal_decider.py:366`）：`conf = 0.3 + 两侧分(_side_score×2) + 位置分(_pos_score)`，只反映**检出流几何证据**（点数/跨度/穿越点偏筐心）。网信号对它零贡献。
- **篮网门**（`net_motion.py:240 net_evidence_pass`）：只测 `status=="high"` 的行；`post < NET_STATIC_TH`（网静止）或 `local=False`（全局噪声伪装）→ **直接改 status** 降 review。不动 conf。fail-open（测不到=不降）。
- **档位规则杂糅**（`goal_decider.py:402-414`）：阈值分箱（conf≥0.7→high）之外还有四条直接改 status 的旁路——硬门三条（`low_reason`→low；`entity_review`/`geom_review`/`pop_back`→review）+ 两条 2026-08 时代的特征补丁（R1 升绿：`|off|≤0.20 且 above_n≤3`；P1d 降档：`above_n≥8 且 below_span≤0.30`）。
- **B2 注入行**（`net_clusters.py`）：由网动簇触发，却**没有** net_* 字段（UI 显示 null）；①修完后几何分已进公式，网分项天然缺失。

用户不满意的正是这个形状：网证据是仅次于几何的第二大物理信号，却游离在置信度之外、以「暗降档」的方式起作用——用户在 UI 上看到 0.75 分的 🟡 行，算式里找不到它为什么不是 🟢。

## 2. 目标语义（一句话）

**档位 = 硬门裁决 ? 硬门档 : 阈值分箱(conf)，其中 conf 含网分项；网测量覆盖全部行。**

两个用户裁定合成后的精确语义：

| 裁定 | 落地 |
|---|---|
| 网证据体现在置信度 | 网信号变成 conf 的加减分项（§3.1），不再直接改 status |
| 所有球都走篮网判断 | `net_evidence_pass` 测量对象从 `high` 扩到**全部行**（§3.2） |
| 保留硬门 | `low_reason`/`entity_review`/`geom_review`/`pop_back` 四条物理否证/复核门**原样保留**，硬门行的档位不参与阈值分箱，测网只记录不改档（§3.3） |

## 3. 设计

### 3.1 网分项进公式

```
conf = 0.3 + 两侧分 + 位置分 + 网分
```

网分取值（**初始值按「首轮重放档位迁移 ≈ 现行网门行为」推导，八场定标后可再调**）：

| 网信号 | 网分初始值 | 依据 |
|---|---|---|
| 网静止（post < NET_STATIC_TH） | **−0.20** | 单向证据铁结论（2026-09 取证：网静止⇒大概率没进，08-29_3 假绿的 74% 形态）。现行行为=high→review；−0.20 使 0.70→0.50 落 review，方向与幅度对齐现状 |
| 网亮但非局部（post≥TH 且 local=False） | **−0.10** | 全局抖动/编码噪声伪装（v14 局部性门）。比「真静止」轻：信号被污染≠网没动 |
| 网动且局部（post≥TH 且 local=True） | **0** | ⚠ **不许给正分**：打铁弹出蹭网/砸筐沿传振/贴网外侧扫落同样让网强烈摆动（08-28/08-22 假绿主形态，5 例目检定性）——「网动不升级」是五轮取证换来的结论，实现时不得「顺手对称化」 |
| 测量缺失（fail-open） | **0** | 证据缺失不当否证（现行同款） |

- conf 下限自然 ≥0.15（0.3+0.05+0−0.20），无需 clamp；仍 round 2 位再比较（现行纪律）。
- R1/P1d 若按 §3.4 保留为 conf 修正项，须加在**几何分部分**；网分最后加——保证「网静止 −0.20」对任何几何分组合都压得住（不被遮挡补偿抵消回 high）。
- `net_post`/`net_ctrl`/`net_local` 落值全行化（§3.2），UI 依据卡算式行追加「网 −0.20（静止）」这样的项。

### 3.2 测量全覆盖

`net_evidence_pass` 的测量对象 `highs = [e for e in events if e.status == "high"]` 改为全部事件行。要点：

- **成本**：~0.7 分/候选，八场约 1000+ 行 vs 现只测 high 的几百行，增量 ~10 分钟/八场，一次性（sidecar 缓存命中后重放秒级，与现状同）。
- **sidecar 复用**：测量参数（窗口/TH/K/ROI）不变 ⇒ `NET_SIGNAL_VER` 不升号，旧 sidecar 里 high 行的测量原样吃回，增量只测未覆盖行。键（round(t,2) 字符串）与身份（video+hoop+ver）不变。
- **进度提示**：`stage_cb` 文案里的候选数口径从「N 个候选」语义变为全行数，照实报。
- low 行（low_reason 硬门）也测：conf 完整性（用户裁定「不然分值不准」）+ UI 可解释，档位仍由硬门定。

### 3.3 档位裁决优先级（从高到低）

1. `low_reason` 硬门 → **low**（物理否证：无实体量级检出/证据点太少。网动不给正分 ⇒ 网信号救不了它，单向证据原则自动成立）。
2. `entity_review` / `geom_review` / `pop_back` 硬门 → **review**（疑似类，强制人工。**不被网分拉高也不被压低**——pop_back 是「疑似弹出」非确证，历史上误伤过才只强制复核）。
3. 其余行按阈值分箱：conf ≥ HIGH_CONF → high；≥ MIN_CONF → review；< → low。

即 `status = 硬门档 if 硬门 else 阈值分箱(conf)`。`net_evidence_pass` 的降档两句（`e.status = "review"`）删除——它的输出从「改档」变为「写 net_* 字段 + 网分值」（网分在 decide_goals 里进不了公式——测量是后置 pass——所以实现形态：net pass 计算每行网分，**回写进 conf 并按上表重分箱非硬门行**；等价于把公式最后一项的求值时机后移，公式文本不变）。

时序纪律：`decide_goals` 仍产**几何 conf** + 初始档位，「证据点太少（<0.50）」硬门在几何 conf 上判（不随后置网分漂移——网分只把非硬门行往低箱推，不会把硬门 low 行救回）；网分回写与重分箱只发生在 net pass。冷却释放（v14）的 `pre_status` 对照快照口径在实现计划里核对（它消费「网门降级集」，降级语义改为扣分后集合定义要跟着改）。

### 3.4 R1 / P1d 处置（主案：删除，八场对齐验证）

- **主案**：删除 R1 升绿与 P1d 降档两条 status 补丁。理由：它们是「公式信息量不足时代的一票补偿」，其输入特征（off/above_n/below_span）已全在两侧分/位置分的自变量里；统一公式后保留只会再造一条「算式解释不了的档位」。
- **验证**：八场重放对比删除前后的档位迁移表与指标；若 high 查全显著劣化（R1 救过的被遮挡干净球掉回 review），备选方案是把 R1 转为几何分修正项（+0.0x，加在网分之前），P1d 同理（−0.0x）。**先删后测、劣化再补**，避免一上来两套机制叠加。
- `pop_back` 仍是字段（UI 复核文案用），只是裁决走硬门表。

### 3.5 B2 注入行

- 网分按 **0** 计（不扣不加）：簇触发判据=同款局部性门 ⇒ 网证据天然成立；而全行测量（§3.2）落下的实测 `net_*` 值仅供 UI 展示——注入行 t 是链内插时刻，测量窗（t+0.45~0.95s）可能错过摆动相位，测出「静止」再扣 −0.20 是对同一证据的双重惩罚/误伤。几何分①已进公式：conf = 0.3 + below 分 + 位置分，实测分布 0.44~0.70。
- **status 恒 review 不变**（宁多勿漏裁定，2026-09-25）：即使算式达 0.70 也不升 high。B2 行视作自带硬门。

### 3.6 阈值重标定（八场定标流程）

网分使 conf 分布整体下移，`HIGH_CONF=0.7`/`MIN_CONF=0.5` 需重标：

1. 八场重放产出每行 `(conf, status, truth 匹配)`；
2. 扫 (HIGH_CONF, MIN_CONF) 网格，对每组报告：三档行数、high 查准/查全、review→low 迁移量；
3. 选「high 行数最接近现状、high 查准不降」的点；0.7/0.5 若仍在帕累托前沿上就不动（少动一刀是一刀）。

**定标结果（2026-10-11，用户裁定）**：目标函数取「真进球与误判平衡」而非本节示例口径 → **HIGH_CONF 0.70→0.65**（边际交换率拐点：0.70→0.65 为 1.7 假绿/球，0.65→0.60 跳至 4.7；0.65 落点 high 1243 / 假绿 469 / 命中 774）。MIN_CONF=0.50 不动（扫描列全同，无杠杆）；NET_SCORE_GLOBAL=−0.10 不动（收紧 −0.20 为 60 假绿:13 命中=4.6:1，与「保标注进球」冲突，数据见 诊断/2026-10-11-网分v18/报告.md ③）。

### 3.7 UI 文案

- 依据卡（`BasisPanel`）：算式行加网分项；🟡/⚪ 行的「只测 high」「未经网区判据」warn 块（e2e A-3 钉过）改为实测网值或「未测（fail-open）」。
- `evaluate.py` 口径不变，但**报告必须附档位迁移表**——尤其 review→low 的迁移会让「假绿」计数自动下降（low 不计假绿），那是口径移动不是精度提升，不附迁移表会被误读为变好。

## 4. 验收纪律

- `LOGIC_VERSION` 17→**18**；`NET_SIGNAL_VER` 不动（§3.2）。
- 八场 evaluate 对比。⚠ 实况约束（2026-10-11 核实）：v16 轮八场重放产物在 Temp、已删；`work/` 里 truth 场存档是 v10–v13 时代产物且 08-21_1/08-22_1 **视频已移走**。本轮重放前先盘点视频在位：缺视频场按 fail-open 记录、单列「环境受限场」，不静默混入总账；必要时请用户把归档视频移回。
- 交付物：八场指标表 + 档位迁移表 + review→low 抽样 20 行人工看片清单（终裁=用户看片纪律）。
- 全量 pytest + 相关 e2e（A-3 文案改动会牵动 bay spec 断言）。

## 5. 范围外

- 网信号测量参数本身（窗口/TH/K/ROI）不动——本设计只改「测量结果如何参与裁决」。
- E1/E2 决策包、竖屏问题②（挂起）、seg2/seg3 筐位劫持等遗留项，互不相干。
- 「网动给正分」的对称化改造：物理上被证伪，永不做（除非未来有逐球身份信号能区分擦网/入网——那是 v2 逐帧跟球的事）。
