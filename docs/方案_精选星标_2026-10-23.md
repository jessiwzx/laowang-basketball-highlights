# 方案：★ 精选标记（单条从"精彩球"里挑）

> 2026-10-23 grill-me 澄清定稿。状态：**待用户确认后开发**（未动代码）。
> 关联需求：`docs/需求池.md` R-024。

## 1. 问题诊断（为什么不能靠"少勾几个"）

用户诉求：单条视频只想从**全部进球**里挑**精彩的**几条出，而不是把勾选的全出了。

现状是**一维**：`row[0]`（表格「进片」列，`selection`）同时承担三件事：

| 用途 | 出处 |
|---|---|
| 认定这是进球（人工核对） | `load_events_table` 从 `selection.json` 恢复 |
| 决定集锦里有哪些球 | `_picked_rows` 只取 `row[0]` 的行（`app.py:1381`） |
| 统计命中率的分子 | `build_goal_stats` 的 `picked = [r for r in rows if r[0]]`（`app.py:1319`） |

⇒ 为了单条"少勾"会让**集锦漏球 + 命中率变小**。所以缺的是一维，不是操作习惯：

- **进片**（`selection`）：这是进球 → 进集锦、进统计。数量多（全场 20 个）
- **精选**（`starred`，新增）：这个值得单独发 → 只影响单条生成。数量少（5 个）

不变式：**精选 ⊆ 进片**。

## 2. 设计

### 2.1 数据

- 新 sidecar `work/<视频>/starred.json`：`["01:23.4", ...]`，与 `selection.json` **同口径**（键 = 原始检测时刻，走 `_raw_time_keys`，换偏移不丢、重跑检测后对不上的键自然作废）。
- 行结构由 7 列扩到 **8 列**：`[selection, t, status, conf, before, after, tag, starred]`。
  - 现有代码读 `row[6]` 全部带 `len(r) > 6` 保护（`app.py:764/1324/1330/1972`），追加第 8 列安全；行构造只有一处（`app.py:833`）。
- 不变式的**三个维护点**（缺一处就会出现"精选了但没进片"）：
  1. 打星（`starred=True`）→ 后端**自动把 `selection` 置 1**；
  2. 取消勾选（`selection=False`）→ **同时清 `starred`**；
  3. 读盘时纠偏：`load_events_table` 里 `starred = starred and selection`（挡历史脏数据/手改 sidecar）。

### 2.2 接口

| 端点 | 改动 |
|---|---|
| `PATCH /api/events/{key}` | `EventPatch` 加 `starred: bool \| None`；两处写盘保持两表一致 |
| `GET /api/session`（行 payload） | 每行加 `"starred": bool` |
| `GET /api/gen/choices` | `output=single` 时在 choices **头部**插入 `GEN_STAR_LABEL`；`default` 改为 `[GEN_STAR_LABEL]`（精选为空时 `default=[]`）；`stats` 追加 `｜★ 已精选 N 球` |

**精选项文案用固定串**：`GEN_STAR_LABEL = "★ 精选（只出打星的球）"`，**不把 N 球拼进字符串**。
理由：合集项那次已经吃过"展示串即勾选值、随模式变导致勾选丢"的亏（P0-1）。N 球只出现在 `stats` 里，不进 value ⇒ 比对永远可靠，`_is_star_item()` 仍是单点白名单。

### 2.3 生成

- `_picked_rows(table, tag_filter="", starred_only=False)`：加参数筛 `row[7]`。集锦路径不传（行为不变）。
- `generate_singles`：遇到精选项 → `starred_only=True` 取行；其余项（合集/标签）逻辑不变，**跨项按时刻去重**照旧。
- 精选为空时报错文案：`精选里没有可出的球——先在表格里给想单发的球按 S 打 ★`（**不回退到全部勾选**：静默回退会一次发出 20 条）。

### 2.4 界面

- **★ 列加在末尾**（置信度之后，宽 40，★ 金黄 / ☆ 灰）。← 关键取舍，见 §5。
- 键盘：`s` = 切换当前行的星（已占用键：`↑↓/space/x/d/k/j/l/←→/1-9/?/ctrl+z`，`s` 空闲）。
- 顶栏在「已勾选 N%」旁加 `★ N` tag（打星数一眼可见）。
- 单条弹窗：清单变成 `★ 精选（只出打星的球）` + `视频合集（全部勾选的进球）` + 各标签；**默认只勾精选项**。
  切输出模式的勾选映射规则：标签项一律保留；合集类项（合集 ↔ 精选）按目标模式的 `default` 换：
  - 切到 single → 合集项换成精选项（精选为空则老实保留合集项，并在弹窗提示先打星）；
  - 切到 reel → 精选项换回合集项。
- 旧 gradio 界面不动（沿用既有裁定：`project_rows` 仍投影 4 列，旧界面看不见也打不了星）。

## 4. 验收

1. **单测**：`starred` 三条不变式各有独立用例（打星补勾 / 取消勾选清星 / 读盘纠偏）；`_picked_rows(starred_only=True)` 只回精选；精选项生成只出打星的球且命名字段不变。
2. **e2e**：点 ★ → 该行勾选自动变 true → 打开单条弹窗默认勾「★ 精选」→ 生成结果条数 = 打星数；`TAGCELL=4` 与所有 `td.nth(2)` **保持不变**（星列在末尾，若这些断言需要改，说明列插错位置了）。
3. **md5 对拍**：`2026-10-17_1` 上横/竖集锦成品与改动前**逐字节一致**（精选不参与集锦，理论上必然一致，仍要实测）。
4. 全量 `pytest`（含 `test_app.py`）+ e2e 192 项。

## 5. 关键取舍与风险

**① 星列放末尾而不是放「进片」旁边。**
e2e 里有 10+ 处按列序取单元格（`td.nth(2)` 时刻、`nth(3)` 档位、`TAGCELL=4` 标签）＋ CSS `.row-miss td:nth-child(3)`。放末尾 ⇒ **一处都不用改**；放中间 ⇒ 十几处索引全要 +1，漏改一处就是假绿/假红。UX 代价是星标离缩略图远一点，可用 `s` 键补。

**② 不变式有三个维护点，最容易漏的是"取消勾选要清星"。**
漏了就会出现"精选里有个没进片的球" ⇒ 单条发出一个集锦里没有的片段。用例要单独钉住。

**③ 精选项文案必须固定串。**
一旦把"N 球"拼进 value，精选数一变勾选就丢——和合集项那次同一个坑。

**④ 兼容性**：老数据没有 `starred.json` ⇒ 空集，全部未打星，行为与今天一致。上行无 schema 版本号，不需要迁移。

**⑤ 上游同步**：按既有惯例两仓同源同改；`bbh/app.py` 仍走**补丁移植**（上游是 HSV 版），不整文件覆盖。

**回退**：全部改动集中在"新增一维"上，回退只需 revert 对应提交；`starred.json` 是纯新增文件，旧代码忽略它，无数据损坏风险。
