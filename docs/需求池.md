# 需求池（Backlog）· 视频剪辑YOLO

- 建立：2026-10-15
- 用途：**收拢"能做、但优先级不够 / 暂时不做 / 待条件触发"的需求**，一条一编号，随时可捡起。
- **重要**：进池 ≠ 要做。池子是"备忘"，不是"待办"。**只有你点头的条目才会进入实施**（且按项目规矩：先出方案 → 你确认 → 才动代码）。

---

## 0 三条维护规则

1. **什么进池**：任何被评估过、结论是"可做但暂不做 / 优先级低 / 条件触发"的需求。**每条必须写清「触发条件」**，否则等于没记。
2. **什么不进池**：
   - **已证伪关闭**的 → 进 §3「已否决」专区（避免反复重议）；
   - **你已明确裁定不做**的 → 进 §2.1（避免以后又被翻出来问一遍）；
   - **正在由别的会话推进**的 → 标 🔵，防止本仓重复动手。
3. **怎么更新**：每次谈完一个需求、或做了一个，就回来改这一份（改状态 / 补资产 / 移区）。**不要新建第二份池子。**

| 🔵 **外部进行中** | 另一个会话/线路在做，**本仓勿重复动** |
| ✅ **已完成** | 做完的留一行做索引 |

**真实瓶颈不在代码**：11-07 覆盖率 61.8% 的根因是网材质与机位仰角（10-23 与 11-06 筐同为 44×18，真球网信号差 4.4 倍）；漏检真漏仅 13 条（1.7%），检出能力已封顶。**再提升只能靠换机位 / 正对筐口 / 高对比度网，非代码。**
**重启条件**：①用户明确「宁漏不剪错」⇒ 可做 A 规则；②拿到新场次球单 ⇒ 扩样本重测。除此两条一律不再提。
