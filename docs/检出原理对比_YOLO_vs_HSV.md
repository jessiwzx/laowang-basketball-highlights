# 检出原理对比 · YOLO vs HSV

回答「整体 YOLO 实现和基于 HSV 实现的原理和差异」。
两边的代码：`bbh/detector_yolo.py`（默认）与 `bbh/detector.py`（对照），
`bbh/detector_switch.py` 一键切换（`BBH_DETECTOR=yolo|hsv`）。

## 0 先说共同的部分（也是能互换的原因）

检出层在整个系统里只干一件事：**逐帧看视频，把"疑似球"变成一串带
时刻的坐标点**（`BallPos: t/x/y/area`），喂给下游判定器
（`goal_decider.py` 穿筐状态机 → 三档置信事件）。判定几何、篮网证据、
静止链过滤、剪辑渲染全部在下游，**与检出器是谁无关**。

所以两种实现的契约被钉成完全一致（同签名、同坐标系、同时钟）：
- 入参 `detect_positions(video, calib, ...)`，出参 `(positions, meta)`；
- 坐标统一折算回**标定参考帧坐标系**（减去镜头位移），判定器全程用同一套标定几何；
- 时钟统一容器 PTS 优先、读不到回退帧号/fps；
- 甚至筐口条带忽略（band_filter）两边都保留。

差异只在「**一帧里怎么把球认出来**」。

## 1 HSV 实现（原方案）：颜色门 + 几何筛

`bbh/detector.py`，纯 OpenCV、CPU 毫秒级。每帧的流程：

1. **取色域**：标定时你在界面上点球（1~3 次），生成 `hsv_low/hsv_high`
   写进 calibration.json——这就是检测器的"知识"，**每场都得点一次**。
2. **裁筐周 ROI**：只看篮下禁区那一小块（筐矩形放大若干倍），省算力
   也避开观众席里的橙色衣服。
3. **颜色掩码**：ROI 转 HSV 色彩空间，`cv2.inRange` 把落在色域内的像素
   染成白，其余全黑。
4. **连通块分析**：`findContours` 找白色块，每个块是一个"球候选"。
5. **几何三层筛**：面积上下限（太小的噪点、太大的色块毙掉）→
   形状（占最小外接圆 ≥0.45，篮球近圆；篮网/手臂细长条会被毙）→
   筐口平面 ±1/4 筐高条带忽略（贴着筐平面飞的静块多半是网结）。
6. 过筛的块 → `BallPos`（t、质心、轮廓面积）。

**本质**：它不是在"识别球"，是在找"符合橙色范围+圆+尺寸"的像素团。
知识全部来自你点的那几下颜色，加一组手工阈值。

## 2 YOLO 实现（本工程默认）：自训 CNN 直接认球

`bbh/detector_yolo.py`，自训 YOLOv8n（`bbh/weights/best.pt`，约 6MB），
训练数据是 7 场比赛的逐帧标注（ball/hoop 两类）。每帧的流程：

1. **整帧推理**（不裁 ROI，`imgsz=1024`）：把整幅画面缩到 1024 输入
   卷积网络，网络输出所有 ball 类检测框 + 置信度（取 conf≥0.03——
   特意压得很低，召回优先）。
2. **只留 ball 类**，多候选帧按置信度取最优。
3. **框转点**：检测框 → 等面积圆估算面积 `π/4·bw·bh`（与 HSV 的轮廓
   面积量级可比，下游阈值不用改）。
4. 筐口条带忽略与 HSV 相同；其余几何筛不需要了——**网络自己学会了
   "什么是球"**，形状/颜色不再需要人工规则。

**本质**：知识在训练数据里，权重文件一次训练、所有场通用；
标定只剩"点筐口两端"（判定要用的几何），**点球那一步不再必要**。

## 3 关键差异一览

| 维度 | HSV | YOLO |
|---|---|---|
| 判据来源 | 你点的色域 + 手工阈值 | 训练数据学出来的特征 |
| 标定依赖 | 每场点筐 + 点球（色域） | 只点筐（色域字段保留兼容但不再用于检测） |
| 光照/场地变化 | 脆——顶棚暖反光 S=37 一样过色域、链被静块劫持 | 鲁棒——不依赖具体色值 |
| 观察范围 | 只看筐周 ROI | 整帧 1024 |
| 算力 | CPU，毫秒级/帧 | 需 GPU（实测 ~26 帧/秒）；CPU 可跑但慢 |
| 典型错误形态 | 色域漂移→漏检；静块/皮肤→假阳性（靠静止链过滤兜） | 高分噪声多（离球 3s 外给高档）；判定点时刻偏 0.2~0.5s |
| 面积口径 | 轮廓面积 | 框等面积圆（唯一语义差异，量级可比） |

其中"判定点时刻偏移"值得单说：HSV 的真值锚定在它自己选的检出点上，
YOLO 选的穿筐时刻与它差零点几秒——球照常判出来，但**成片剪辑点会
差 0.3 秒左右**，是产品可见差别；评测时把时刻因素剔除后两条臂基本打平。

## 4 实测效果（7 场 890 球，官方口径 + 扣时刻口径）

| 指标 | HSV | YOLO（c03@step1） |
|---|---|---|
| 官方口径查全/查准（0.2s 行锚定） | 82.4% / 87.5% | 69.6% / 71.8% |
| 扣掉时刻因素后查全 | 82.4% | 80.9%（剔 09-19 后 **87.7%，反超**） |
| 真漏 | 1 球 | 3 球 |
| 假绿（纯噪声） | 105 条 | 142 条（+37，**唯一真实短板**） |
| 需人工复核 | 108（6 场） | 92（6 场，更少） |

一句话：**判定能力打平甚至略优；YOLO 换来的是标定简化与光照鲁棒性，
代价是 GPU 依赖与更多的高分噪声**（后者方向明确：困难负样本/近筐
双层 conf 门可治，属检出侧参数问题，不是原理缺陷）。

## 5 工程差异（同一份代码里怎么共存的）

- 同签名对齐：`detector_yolo.detect_positions` 逐一对齐 HSV 版契约，
  `pipeline.py` 只改了 import 来源——判定器零改动。
- 检出流缓存隔离：检出器名并入 `DETECT_VERSION` 指纹，切
  `BBH_DETECTOR` 自动作废旧缓存，两种检出流不互吃。
- 静止链过滤独立可选（`BBH_STATIC_FILTER=orig|b1|b1m`，默认 b1m）——
  这层是 HSV 时代为治静块假阳性写的，YOLO 下同样受益。
- 出手回扫（A2）与运镜跟球（A3）**仍是 HSV**：它们也用颜色找球，
  但本工程只换了主检测（A1）这一处（性价比最高的替换点）。
