## 0 目标

v18 官方口径（7 场 890 球）：查全 76.6% / 查准 58.7% / 漏检 16.5%（红线不过）；剔 09-19_1 后 6 场 771 球：查全 **82.9%** / 查准 **60.8%** / 漏检 **12.8%**。

本方案目标：**用人工裁决的 hard-case 归因 v18 判定规则在哪判错 → 最小改动修订 → 回归集对拍 → 用户决策是否升 v19。** 只动判定层（`bbh/goal_decider.py` 打分参数 + 网分档位），不动检测器、不动溯源链。

## 1 判定层现状（评审用）

**三档输出**：`high`（自动绿）/ `review`（待复核）/ `low`（低置信，默认不勾选）。

**置信度公式**（`goal_decider.decide_goals`）：

```
conf = 0.30
     + _side_score(above_n, above_span)   # ≥2点且跨度≥0.2s→0.20；≥2点→0.14；1点→0.05
     + _side_score(below_n, below_span)
     + _pos_score(|cross_off|)            # POS_TIERS: ≤0.1→0.20 … ≤0.5→0.06
     + net_score(net_post, net_local)     # 静止(<5.0)→−0.20；非局部→−0.10；网动/未测→0
status = low if low_reason else review if 硬门 else high if conf >= HIGH_CONF(0.65) else review
```

**四道硬门**（v18 起不删事件，只降档 + 记 `review_reason`）：规则A 几何（`|off|>0.30` review / `>0.45` low）｜下落校验（`descent < max(3px, 0.16×筐高)`）｜实体校验（无球体量级检出）｜弹出否决（`pop_back` → review）。`b2` 注入行恒 review、网分恒 0。

**实测可复现性（本方案关键前提）**：用 events.json 的聚合字段离线重写上述公式，对 7 场 2533 条事件：
- 不含网分 → 仅复现 56.8%（说明网分确实写进了 conf）
- 含网分 → **复现 95.9%**（2429/2533），剩余为 `b2` 注入行与网分临界样本，可补齐

→ 结论：**分数类旋钮可完全离线复算，毫秒级出全 8 场结果**，不需要重放、不需要重扫。

### Step 1.5 · 三道护栏重议（阻塞 Step 2，待用户裁定）

Step 1 已经证明：**目标（查准 +5pct、查全不塌）本身可达**，卡住的是三道人设护栏本身不合理：

1. **护栏 A（active fp 降级 ≥90%）**：族内最高 37.5%。因为 33 条硬核与真进球同特征，打掉它们必然连带杀掉真进球（权衡曲线：guardA 72% 时查全只剩 73%，82% 时只剩 41%）。
2. **单场 review +≤20**：最低可达 +24（09-11_3），只差 4 条。
3. **反向监测「非自动档不得增加」**：任何降级都会让部分真进球掉出自动档，这条红线数学上等价于「禁止任何降级」，应改为有上限容差。


### Step 2 · 规则修订候选（开关化 + 参数白名单）

**白名单（只允许动这四个）**：

| 参数 | 含义 | 离线可算 |
|---|---|---|
| `HIGH_CONF` | 绿/黄分界线 | ✅ |
| `POS_TIERS` | 位置分档 | ✅ |
| `CONT_SPAN_SEC` | 连续证据跨度门槛 | ✅ |
| `NET_SCORE_STATIC` / `NET_SCORE_GLOBAL` | 网分扣分值（改造成可配，不动测量） | ✅ |

**黑名单（本轮一律不动）**：

| 参数 | 为什么禁 |
|---|---|
| `NET_STATIC_TH`(5.0) | 它同时是**测量判据**（`net_motion._window_scores` 用它决定 `net_local`）和打分判据；改它要重测网信号 = 重扫视频（成本 ×10） |
| `MIN_CONF`(0.5) | 一动触发**冷却释放**二阶效应（低置信不占冷却钟），离线复算测不准 |
| `X_MARGIN` / `POPBACK_SEC` / `MAX_CROSS_SEC` / `DESCENT_RATIO` | 属"重新选点"，需点流重放；留待第二轮 |

**原则**：保持 v18「只降档、不删事件」。实现纪律：生产 `bbh/` 代码在过门线前零改动，改动落在候选分支。

**代价护栏**：单场新增 review **≤20 行**（6 场 ≤120）。现状 6 场 high 1239 / review 506 / low 450，review 已占 23%；降档就是把自动绿变成人工复核，超上限视为"拿人工成本换指标"，不予通过。

### Step 3 · 回归对拍（三级阶梯，按成本递进）

| 级 | 手段 | 能测什么 | 成本 | 启用条件 |
|---|---|---|---|---|
| ① | **离线复算器** | 白名单内全部旋钮 | 毫秒/场 | **必须先过自校验** |
| ② | **点流重放**（`replay_layer.py`） | 选点类旋钮（第二轮） | 秒~分钟/场 | 候选超出白名单时 |
| ③ | **官方 KPI**（`tools/evaluate.py`） | 最终裁判 | 分钟 | 过门前必跑 |

**离线复算器硬验收**：必须 100% 复现 v18 现状——① 7 场 2533 条 `status` 逐条一致；② 官方 KPI 四个数 **1051 自动档 / 639 命中 / 82.9% 查全 / 60.8% 查准**全部对上（含 `deleted.json` 剔除、0.2s 行锚定、09-12_1 间隙球白名单）。任一对不上 → 停用该工具，退回重放路线。

**三段验证**：① 调参集（79 条反馈 + 同场 KPI）② 同场验证（34 条，只此一次）③ 陌生场 08-29_3（只此一次）④ 官方 6 场 771 球全量 KPI
**反向监测**：4 场（10-10_1 等）翻案数不得增加（同源点流前后对比）。

### Step 3.5 · 门线（grill 裁定：目标值化 + 条件门 + 双护栏）

不做固定 `查准 ≥65.8%` 硬门。原因已量化：**反馈只覆盖 412 个假绿中的 135 个（33%）**，调参集只覆盖官方假绿 72 条——即便全中且零误伤，查准上限也只有 639/979 = 65.3%，低于 65.8%。门线必须承认标注量约束。

**门线定义**（**已代入 Step 0 实测**：A = 89）：

1. **可达上限**：`cap = 639 / (1051 − A)`，A = 全量 active fp（官方 6 场内）= **89** → `cap = 639/962 = **66.4%**`
2. **主门**：`查准 ≥ min(65.8%, cap − 1pct)` = **min(65.8%, 65.4%) = 65.4%**，且必须高于基线 60.8%
3. **护栏 A（不许浪费标注）**：在 active fp 集（89 条，其中调参 59 / 同场 17 / 留出 13）上，**降级命中率 ≥90%**——用户标过的假绿必须基本被打掉
4. **护栏 B（不许用查全换查准）**：同场真进球集上**误伤率 ≤3%**（约 ≤7 个，等价查全 ≥81.9%）
5. **护栏 C（成本）**：单场新增 review ≤20 行
6. **逐场红线**：任一场查全降幅 >5pct = 崩场，整轮回滚
7. **反向监测**：3 场（10-10_1 / 09-24_1 / 10-16_1）真进球落在非自动档的条数不得增加（基线 70 / 24 / 68）

不过门 → 最多再调一轮；两轮不过 → 停手汇报，不强推。

### Step 4 · 上线决策（用户拍板，独立一步）

- **升 `LOGIC_VERSION` → 19**（不做隐藏开关：新规则必须带新版本号，否则口径不可追溯）。机制上**不触发重扫**——`pipeline.py:553` 仅在同版本时复用事件，换版只重放判定器（秒级）。
- **历史场次不主动重扫**；以后谁重新打开某场，会自动秒级重判为 v19。
- **补一份 v19 官方 KPI 表**（同 7 场同口径，与 v18 并排留档），回归基线同步更新到 v19。
- **回滚**：常量改回默认值 + 版本号回 18，重放一次即复原。

## 4 风险与影响面

| 风险 | 说明 | 对策 |
|---|---|---|
| 标注量不足 | 反馈只覆盖 33% 假绿 | 门线目标值化 + 可达上限公示 + 护栏 A 保证不浪费已标注 |

| 反馈本身误标 | 人工裁决也可能错 | 抽 20 条目视复核，错标剔除并记录 |
| 用查全换查准 | 收紧阈值必然杀真进球 | 护栏 B（误伤 ≤3%）+ 逐场 5pct 红线 + 反向监测翻案 |
| 复核量暴涨 | 降档=人工成本 | 护栏 C（单场 ≤20 行） |
| 离线复算与生产漂移 | 复算器是另一份实现 | 100% 自校验（2533 条 status + KPI 四数），不中即停用 |
| 判定层是生产核心 | 影响每场每球 | 开关化 + 默认值 = v18 + 版本号隔离 + 一条命令回滚 |

**影响面**：仅判定层打分参数；检测器 `best.pt`、溯源链 shooter、前端一律不动。
