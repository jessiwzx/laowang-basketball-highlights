- 前置结论（同日调研，见《方案_YOLO标定_竞品调研与实施》）：无竞品做"点选球颜色"标定；颜色标定是 HSV 时代产物。本方案即该调研的落地。

## 0 裁定带来的三个直接后果

1. **R-014（自动定筐建议）→ 否决**：筐保留人工点选（NUSTemple 同款决策，零域风险）；
2. **R-013（标定页预览失真）→ 被本方案吸收**：球点选/HSV 环节退役后，第③④步改造为新形态；
3. **标定向导从 4 步瘦身为 2 步操作**："点筐口两端 → 看一眼 YOLO 检出预览 → 完成"。

## 1 现状链路（改动前的精确事实）

| 环节 | 现状 | 裁定后 |
|---|---|---|
| 步②"标关键点" | 点筐口两端 + **球 1~3 次**（后两点算筐矩形，球点算 HSV 范围） | **只点筐口两端** |
| 步③"生成并验证" | 预览画 **HSV 命中**（`overlay_preview`）——验证的不是真检测器 | 预览画 **YOLO 检出**（`best.pt` classes=[0]）+ 筐框 |
| 步④"微调 HSV" | S/V 滑块，只影响 HSV 对照版与 shooter 种子 | **整体移除**（YOLO 模式） |
| `Calibration.hsv_low/high` | 来自球点选 ±(4,40,40) 余量 | **固定默认橙球色域**（字段保留，shooter 兼容） |

**谁在消费 `hsv_low/high`（决定风险面）**：
- `shooter.py:186 _scan_hsv`（A2 回扫口径，含 S≥88 地板）+ `shooter.py:801`（A3 二次精扫）→ **唯一生产依赖，且 shooter 本仓不能动**（另一会话在改）；
- HSV 对照版（`run_app_hsv.bat`）→ 对照/单测用途，可接受默认值；
- `goal_decider` **不读 hsv** → **判定数字零影响**（判定链只吃 YOLO 检出流 + 筐矩形 + 网运动）。

## 3 唯一实质风险与对冲：shooter 溯源行为

球点选退役 → shooter 的色域种子从"点选范围"变"默认范围"，**新场次溯源候选集会变**。对冲分三层：

1. **证据先行（Step 0，只读对拍，改码前跑）**：拿 2~3 场（含最差的 09-04_1），对同一批出手窗口分别用「点选范围 vs 默认范围」跑 `_scan_hsv` 层面的 mask 对比 + 抽样迷你 trace，自动指标（候选数/静块占比）不劣化才开工；
2. **shooter 自带防线**：`SCAN_S_FLOOR`（S≥88 地板，自动滤顶棚反光——09-04_1 低饱点选 S=37 的教训正是被它兜住的）+ 三连单调链 + 静块剔除，色域偏宽时这些门会兜住大部分噪声；
3. **第二步收尾（条件触发）**：等另一会话的 shooter 重构落定——若其新方案不再要 HSV 种子，`hsv_low/high` 字段连同默认值彻底退役，标定只剩筐。

### 3.1 风险实测佐证（2026-10-15 补，7 场点选范围盘点）

对 7 场现有点选标定的 `hsv_low/high` 实际盘点（`视频剪辑/work/*/calibration.json` + 本仓 work）：

| 场次 | H 范围 | S 范围 | V 范围 |
|---|---|---|---|
| 2026-09-04_1 | 0~13 | 111~227 | 87~190 |
| 2026-09-11_3 | 0~12 | 116~215 | 62~148 |
| 2026-09-12_1 | 1~11 | 138~228 | 78~162 |
| 2026-09-19_1 | 0~9 | 112~223 | 66~151 |
| 2026-09-24_1 | 3~11 | 101~188 | 112~199 |
| 2026-10-10_1 | 2~13 | 104~204 | 75~159 |
| 2025-06-28_1 | 8~17 | 75~161 | 75~171 |

结论：**7 场的球色范围高度收敛**（H 全部落在 0~17 的红橙带，S/V 离散度也有限）——固定默认色域与点选结果天然接近。且 shooter 对 S 下限本就有固定地板（`SCAN_S_FLOOR=88`，7 场点选的 S_lo 抬后分别为 111/116/138/112/101/104/88，与点选值几乎无关）、A3 跟球把 V 上限本就放宽到 255——**点选信息真正被消费的只剩 H 带宽与 V 下限**。残余风险集中在**未来出现非橙色球的场次**（失败形态=该场溯源退化、⚪变多，可见可救，不侵蚀进球判定）。Step 0 对拍用含 09-04_1（点选最宽）与 2025-06-28_1（H 偏移最大，8~17）的场做对照。

### 3.2 GitHub 外部佐证（2026-10-15 实搜复核）

用户问"GitHub 上的项目也是这么做的吗"，实搜复核（WebSearch + NUSTemple README 原文核实）：

| 项目 | 球检测 | 球颜色/HSV 标定 | 筐定位 |
|---|---|---|---|
| **NUSTemple/basketball-shot-clipper** | YOLO (yolov8m) | **❌ 完全没有** | **✅ 人工拖框，每视频一次，必需前置**（未标定的视频批量时直接跳过） |
| JadenS180/basketball-shot-tracker（新发现） | YOLOv8 微调（ball/rim/human 三类，imgsz=1280） | ❌ 无 | rim 当检测类别（无标定） |
| nitinhemaraj/AI-basketball-shot-detection | YOLOv8 自训 | ❌ 无 | hoop 当类别 |
| ashwin-aggarwal/AI-basketball-shot-tracker | YOLOv8 自训（ball+hoop） | ❌ 无 | hoop 当类别 |
| griftt/ball-yolo | YOLOv11 自训 | ❌ 无 | rim 类（动态） |
| Val1t3/court-vision | YOLOv8（球员/距离） | ❌ 无（颜色只用于队伍聚类） | 人工单应点选标定（court 映射） |
| fullscale-opencv-yolo（YOLOv3 时代 C++） | YOLOv3 | ⚠️ 带 HSVRangeFinder 工具 | 人工点映射 |

结论：**本方案的裁定（球纯 YOLO、零球色标定 + 筐人工标定）就是 GitHub 上的主流实践**。最可比的 NUSTemple 与本方案完全同构——球纯 YOLO、零 HSV、筐每视频人工拖框（必需），且同样用 net-motion 证据辅助判定（与本仓篮网运动证据同款）；它甚至没有"验证球检测"步骤，比本方案更彻底。"筐当类别检测"派（JadenS180/griftt 等）对应本仓已否决的 R-015 动态筐。唯一带 HSV 工具的反例是 YOLOv3 时代 C++ 项目的 HSVRangeFinder（调色隔离调试工具）——恰印证 HSV 标定是旧时代产物。颜色在现代项目里的残余用途只剩**队伍球衣归属聚类**（petermartens98、Val1t3），与球检测无关。
