## 3. 验收③：逐帧校正为什么不成立

### 3.1 实测数字（真值＝剪辑台 selection.json，口径同 R-020 Step 0）

| 场次 | 真值球 | v20 查准 / 查全 | v21 查准 / 查全 | Δ |
|---|---|---|---|---|
| 10-17_1 | 152 | 82.71 / 72.37 | 86.36 / **62.50** | +3.65 / **−9.87** |
| 10-23_1 | 135 | 77.50 / 68.89 | 78.23 / 71.85 | +0.73 / +2.96 |
| 10-30_1 | 112 | 63.16 / 75.00 | 64.71 / 78.57 | +1.55 / +3.57 |
| 10-31_1 | 127 | 69.82 / 92.91 | 69.19 / 93.70 | −0.63 / +0.79 |
| 10-24_1 | 122 | 89.22 / 74.59 | 同上（无筐采样） | 0 / 0 |
| **合计** | 648 | **75.49 / 76.54** | **76.09 / 75.62** | +0.60 / **−0.92** |

假绿 161 → 154（−7），命中 496 → 490（−6）。**换了个位置，没有变好。**

### 3.2 根因（两条，都实测到了）

**（1）在打的画面里，筐框本身带 5~9px 的系统偏置 —— 0.15~0.25 筐宽。**

同一时刻同一个筐，检测框随手：

| 帧 | 检测结果 (cx, w) |
|---|---|
| 标定参考帧 PNG | 687.5 / 46.25 |
| 视频帧 t=1128.5（即参考帧那一刻） | **688.75 / 47.5**（一致 ✓） |
| 视频帧 t=1129.0（0.5 秒后，场上有人） | **695.0 / 35.0** |
| 视频帧 t=1120 / t=1150 | 691.9 / 41.25、693.1 / 38.75 |

→ 干净帧上完全一致；一旦进入比赛画面（运动模糊、人物部分重叠），
框会缩 25%、中心右偏 5~7px。这个偏置是**持续的**，20s 采样 + 中值滤波
去不掉（滤波只能去单帧尖峰）。而判定门限是 0.30 / 0.45 筐宽 —— 偏置
已经吃掉了半个门限。

**（2）段内 ORB 本来就是准的，没有漂移可修。**

10-17_1 段2 长 101 分钟，按真进球分四段看 `cross_off`：

| 区间 | 真进球 | v20 中位 cross_off | v21 中位 |
|---|---|---|---|
| 第 1/4 | 23 | +0.008 | −0.256 |
| 第 2/4 | 27 | +0.059 | −0.207 |
| 第 3/4 | 25 | +0.091 | −0.152 |
| 第 4/4 | 18 | +0.070 | −0.147 |

v20 全程贴在 0 附近、无时间趋势（101 分钟累计漂移 ≲0.1W）；
v21 是**整段平移 −0.15~−0.26**，即加进去的是一份常数偏置，不是漂移跟踪。
哪两段被坑也印证了这点：段1/段2 校正量 +13.5 / +9.4px（真进球
`|cross_off|` 中位 0.10 → 0.21），段3/段4 校正量 +1.1 / +0.7px（几乎无变化）。

结论：现有 `c(t) = Δ_hoop − shift_orb` 里真正有信息的成分（漂移）≈0，
有噪声的成分（检测偏置）≈0.2W，而设计把它当信号全量施加了。

## 4. 建议

1. **保留筐检测**（模型里本来就有 hoop 类、5067 个框，零额外推理成本），
   但只用于**桥接/补段**，不用于逐帧搬点。
2. **`HOOP_ENABLE` 默认关**，逐帧校正保留为实验开关；`LOGIC_VERSION`
   不带默认行为变化（无筐采样时逐条等价 v20，已验证）。
3. **真交付换成「自动补段」**：机位被碰 → 从 ORB 位移表检出跳变 → 在跳变后
   取干净帧做新参考帧 → 用筐桥接合成该段标定。这条正是用户要的
   「只标一次」，且已被上表以 ≤0.12W 验证。
   ※ 这需要 pipeline 支持「没有用户标定的段」，属新增设计，需另行确认。

# 附录：只标一次 vs 人工多段（判定层同口径对照，2026-11-07 补）

之前那张表比的是「多段 + 加不加校正项」，用户要的是「只标一次 + 筐跟随」对比
「人工多段」。补做的实验 `sim_one_calib.py`（输出留档 `sim_one_calib.txt`）。

## 方法

两臂输入完全相同：同一份 `positions.json`、同样的切段、同一份网信号 sidecar。
唯一变量＝几何。段 k 的球点搬进段 1 坐标系：`x_cal1 = x_cal_k − 筐心位移_k`，
筐心位移＝两段**标定参考帧**上检测到的筐心之差（干净静止帧，偏置相减对消）。
判据用段 1 的标定。

- **P** 现状：段 k 用自己的手点标定
- **S** 只标一次 + 筐跟随（筐框尺寸按参考帧检测尺寸等比缩放）
- **S0** 只标一次 + 筐跟随（尺寸照搬段 1，假设不变焦）——更保守
- **N** 只标一次、**不靠筐**（等于现在「只点一次、后面不管」）

## 结果（真值＝剪辑台 selection.json）

| 场次 | P 人工多段 查准/查全 | S0 只标一次 查准/查全 | N 只标一次不靠筐 |
|---|---|---|---|
| 10-17_1 | 82.71 / 72.37 | 82.09 / 72.37 | 70.75 / 49.34 |
| 10-23_1 | 77.50 / 68.89 | 76.19 / 71.11 | 37.68 / 19.26 |
| 10-30_1 | 63.16 / 75.00 | 62.59 / 77.68 | — |
| 10-31_1 | 69.82 / 92.91 | 67.96 / 96.85 | 68.18 / 59.06 |
| **合计** | **72.97 / 77.00** | **71.72 / 79.09** | **55.47 / 40.49** |

（合计：P high 555 / 命中 405 / 假绿 150；S0 high 580 / 命中 416 / 假绿 164；
N high 384 / 命中 213 / 假绿 171。S 与 S0 几乎相同，尺寸缩放只值 ±0.2pct。）

## 结论

1. **只标一次 + 筐跟随 ≈ 人工多段**：查全反而高 2.09pct（416 vs 405 个真球），
   查准低 1.25pct（多 14 个假绿）。两边在四场上互有胜负（10-17_1 基本持平）。
2. **不靠筐则崩**：命中 405→213、查全 77.00→40.49pct。筐锚点在这里是决定性的，
   不是锦上添花。
3. 那 1pct 查准的差，量级上比**用户自己两次手画筐框的差异**还小
   （10-23_1 同一物理筐，段1 画 44px、段2 画 40px，差 10%；10-31_1 69 vs 64）。
   也就是说：桥接复现的是"筐心"，筐框宽高只能沿用，误差由手画不一致主导。

## 前提（重要）

本实验假定系统仍**在同样的时刻切段并重开 ORB 参考帧**（＝自动补段已经实现）。
「自动检出机位跳变 → 取干净帧做新参考帧 → 筐桥接合成标定」这块还没写；
现在 pipeline 仍要求每段都有一份用户标定。所以这是"上限能力"的验证，
不是"现状已具备"的证明。
