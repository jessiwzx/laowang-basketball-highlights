# snowroll/basketball_clipper
一句话定位：固定机位篮球进球集锦剪辑单文件脚本（滚动差分扫候选 → 事件聚类 → 轨迹几何判进球 → ffmpeg 剪前3s后1s）｜ stars：1 ｜ 语言：Python ｜ 最后更新：2026-05-12

规模：仅 README + `backboard_ball_detector.py`（904 行），OpenCV+ffmpeg，无学习组件。

## 进球判定技术路线（重点）

三阶段两遍式管线（`backboard_ball_detector.py:680-898` main 流程）：

### Phase 1：滚动差分扫描（高召回候选）
- 每 0.1s 采一帧（帧号取模跳帧 `grab()`），只处理**篮板 ROI**（用户首跑框选，示例 655,320,83,48；球检测区=筐上方一块）。
- deque 缓冲 1.5s 窗口（`buf_size = rolling_window/interval + 1`），当前帧 vs 窗口最旧帧灰度 `absdiff` → 阈值 25 → morph close(3x3) → findContours。
- **球体四重过滤**（`detect_ball`，280-330 行）：面积 [0.25πr², 3.5πr²]（**球径 r 由筐宽/2 估计**，745 行）；距 ROI 边缘 ≥4px（滤边界截断斑）；圆度 4πA/P² ≥0.35；**差分覆盖率 ≥0.55**——在轮廓 mask 内统计 `diff≥阈值` 的像素占比（315-327 行），要求「整个斑块都在动」，比纯形状过滤更硬。
- 变化像素 ≥20 才进 detect_ball（粗门）。

### Phase 2：事件聚类
- 候选按时间聚类，gap ≤2s 合并为事件（`cluster_detections`，351-362 行）；每事件取「覆盖率×变化像素」得分最高的 best_frame 为代表（365-368 行）。

### Phase 3：轨迹分析 + 进球判定
- 对事件中心（跨度>3s 用 best_frame 并把分析窗前延到事件起点）±1s、每 0.05s 重采帧，与**事件前 2s 的背景帧**差分，同款 detect_ball 追轨迹（`analyze_trajectory`，373-439 行）。
- **轨迹去噪**（451-481 行）：若 ≥40% 的轨迹点聚在 2px 半径内（静止伪影众数簇），整簇剔除后再判定；全点聚在 3px 内直接拒绝（`is_static_trajectory`）。
- **镜头漂移修正**（`compute_hoop_drift`，484-523 行）：模板匹配（TM_CCOEFF_NORMED，置信度 ≥0.5）对比第 0 帧篮板 ROI，得 (dx,dy) 修正筐坐标后再判定。README 实测 test-22.mp4 漂移：起始 +2px、11 分钟峰值 +13px 水平。
- **check_basket 判据**（526-584 行）：
  1. 静止伪影拒绝（全点 3px 内）；
  2. Rule 1：轨迹必须至少一点高于筐口（y < hoop_y_rel）；
  3. Rule 2a：上→下穿越，穿越 x 在筐宽 ±4px 内，且**穿越后不得反弹回筐口上方**（弹筐拒绝，567-570 行）→ 进球；
  4. Rule 2b（穿网路径）：球在 event_time+0.3s 内**消失**、最后 x 在筐 ±4px 内、消失时仍在向下运动 → 进球（球入网被遮挡的场景）。
- 进球即 ffmpeg 剪前 3s 后 1s 全画面片段（含音频，libx264 veryfast crf20）。

### 误报控制手段
静止伪影双重拒绝（3px 整体 + 40% 众数簇剔除）、边缘 margin、差分覆盖率、弹筐反弹拒绝、穿网消失判据的方向校验。

## 工程亮点
- 两遍式（0.1s 粗扫全片 + 事件内 0.05s 细分析）：粗扫极快，计算集中在候选事件附近——与我们「扫穿越窗」思路同构。
- 交互标定体验好：进度条选参考帧（A/D 单帧步进）→ 框选两个 ROI 存 txt 复用。
- 调试可视化可选保留（事件双图=原图+差分热力叠加；轨迹图=背景帧+时间蓝→红轨迹+筐口黄线）。
- 模板匹配漂移修正带置信度门（<0.5 返回 0,0 不动）。
- 长事件处理：跨度 >3s 用 best_frame 为中心并向前延伸分析窗覆盖事件起点。

## 对我们项目的可借鉴点

痛点①（FP：弹筐/涮框/打铁弧线）：
1. **「穿越后反弹回筐口上方 = 拒绝」**（`check_basket` 567-570 行）——对弹筐/涮框 FP 是最直接的几何反证：弹出的球会再回到筐平面上方。我们 v11 有下落校验+实体再现校验，但没有显式的「反弹回上方」判据，值得在轨迹链上加一条对照测试（真值集现成，可 A/B 验证能杀多少 FP、是否误伤高抛物线空心球——空心球过筐后不会回上方，理论安全）。
2. **穿网消失判据（Rule 2b）**：把「球在筐附近消失且正向下」当进球正证据（穿网被网遮挡），与我们的「实体再现校验」（把不再现当辅助）是同一现象的两种用法。我们目前只用「再现=没进」否定，可考虑「筐带内向下消失且短时不再现」作加分项，配合 CNN 特征。
3. **轨迹静止众数簇剔除**（40% 占比即整簇删）：我们 HSV 轨迹链里的 C 类静态假斑（固定位置的皮肤/红网斑块）会形成稳定点位，此法可清洗轨迹后再跑几何判据，实现简单（O(n²) 但轨迹点少）。
4. **差分覆盖率 ≥0.55**（轮廓内活跃像素比）：一个介于面积和圆度之间的「实心运动斑」判据，可移植为 HSV 斑块的辅助过滤（HSV mask 内饱和度/亮度变化率）。

痛点②：无可借鉴（无归人功能）。

另：模板匹配漂移实测数据（11 分钟 +13px）从数据上印证我们 ORB 镜头位移配准的必要性；其「漂移修正后再做几何判定」的顺序与我们一致。

## 明确不适用的点及原因
1. **CFR 假设**：全程 `fn/fps` 换算时间、`CAP_PROP_POS_FRAMES` 随机 seek——VFR 视频上时间戳和帧号会系统性漂移（我们已用 pts 解决，不可回退）。
2. **采样率对快速球不够**：0.1s 粗扫只负责触发候选尚可，但 0.05s（20fps）细分析对快速下落的球只能采到 2-4 个轨迹点；他们球径 ~13px（筐宽 26px 的一半）尚可，我们球更小、穿越窗更窄，Rule 2a 的 ±4px x 容差在我们的筐尺度（35-65px 宽）需按比例重标定。
3. **正面机位假设**：球检测区=篮板 ROI（筐上方一块），假设球从正面飞向篮板；我们半场侧面视角球轨迹形态不同。
4. OpenCV VideoCapture 读长视频 + 事件内重新 open+seek 的两遍式在我们 2h 视频上 seek 开销大（PyAV 顺序读更优）。
5. 无任何真值评估，参数全手工——查准无保障。
